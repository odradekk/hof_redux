# 玩法保真基准与差异裁决登记

本登记是 [确定玩法保真基准与遗留缺陷处理](https://github.com/odradekk/hof_redux/issues/3) 的裁决产物。规则部分由用户逐条确认；差异条目按规则分类处理，列出结论与后续归属。后续模块议题不得缩小此处确定的覆盖范围；改动本登记需重新裁决。

## 保真基准规则（已确认）

1. **覆盖基线与完成门槛**：以 docs/legacy 的 45 个玩家能力条目、运营与公共能力清单、内容机器清单（15 职业、193 物品、268 唯一技能、147 怪物、24 地图、90 制作输出）为"完整覆盖"验收基线。每条能力和内容在新版要么有对应实现、要么有明确的不迁移决定。已批准范围例外维持不变：取消闲置删号、无邮件、不兼容旧存档、排除废弃实现、保留城镇留言与外链论坛。
2. **灰色内容处理**：完成门槛只计正式可达能力。有定义但不可达的内容随迁移保留并标记不开放（首期不开放）；有分支无入口的隐藏内容，公开范围归展示议题决定；备用实现中唯一有效的能力并入正式实现。
3. **证据优先级**：静态代码实际行为 > 手册描述；手册仅作设计意图参考；冲突记为差异条目并按缺陷分类处理。旧版可在服务器 Docker 中正常运行（用户确认），运行验证结果优先于静态代码推断。手册核查结论：三个手册文件几乎不含数值公式（唯一数值 `BATTLE_MAX_TURNS` 渲染自代码常量），7 项交叉核对全部一致、0 冲突，覆盖主题有限；手册可作界面文案与新手引导蓝本，不作规则来源。
4. **缺陷三分类与默认处理**：
   - 明确缺陷（内部矛盾、未定义变量、明显笔误）→ 修复，记录旧行为与修复后预期。
   - 疑似缺陷（异常但可能有意）→ 默认保留旧行为，逐条裁决。
   - 平衡性改动（数值、概率、成本）→ 默认不做，改动需单独批准。
5. **公式与资源成本保真**：相同输入下新实现整数结果与旧公式一致，含取整位置、运算顺序、截断与溢出语义。体力恢复比例与上限、制作零费用、拍卖时长与费用、竞技冷却、地图开放时段等资源成本与时间数值原样保留。排除 PHP 浮点伪影、PHP rand 具体序列、历史安全缺陷。每条公式配数值对照测试。
6. **随机与执行顺序**：随机复刻分布、取值区间与抽样次数，不复刻序列；新实现使用可注入种子的 RNG，固定种子确定性重放。行动顺序（含 DELAY_TYPE 两种模式）、状态触发与结算顺序保持一致；判定标准为相同初始状态 + 相同随机输入序列 ⇒ 相同结构化战报。新版战报格式重新设计，不复刻旧 HTML 输出格式。
7. **验证样例**：双层验证。公式级数值对照为主体；另在服务器 Docker 搭建旧版最小运行环境，对代表性战斗场景产出黄金样例，新引擎在相同随机输入下抽检比对。抽样核对，不全量重放。harness 搭建时需用户提供现有 Docker 环境的 PHP 版本信息。

## 新版与旧版可观察行为差异汇总（均已批准）

- 非满级时溢出经验保留并允许连续升级；满级时经验归零，之后不再获得经验（LEG-02）。
- 竞技场超时裁决按实际存活数判定（LEG-03 修复）。
- 敌队毒状态比例判定条件可用（LEG-05 修复）。
- 拍卖结束公式消除未定义变量，明确按上架选定时长到期；纠正先前未经运行验证的“旧版立即到期”表述（LEG-08 修复）。
- 玩家颜色校验严格化（LEG-10 修复）。
- 拆分打工入口不存在（LEG-01）。
- 12 个未开放地图首期不可达（LEG-06）。
- 并发与事务按 SQLite 单事务实现，不复制文件锁行为（LEG-09）。
- AGENTS.md 已批准差异：无邮件、取消闲置自动删号、不兼容旧存档、全新界面。
- 保护选项标识修正，概率为准确的 25%/50%/75%，HP 保护门槛包含等于；用户在战斗契约议题 Q1/Q2 已批准（LEG-13）。
- 空战术统一待机并正常计数；容量下降后隐藏超限配置，不参与战斗（LEG-15，Q4/Q5）。
- 无毒抗时也遵守技能中毒概率；已有毒抗公式保留（LEG-16，Q6）。
- 复活仅选择可复活死者，修复全体复活标记不一致（LEG-17，Q7）。
- “己方咏唱人数以下”正确统计咏唱人数（LEG-18，按明确笔误规则修复）。
- 正式战斗体力先预留、成功结算时扣除；预留仍计入恢复上限，系统故障取消时释放（LEG-19，事务契约 Q5）。
- 地图怪物及世界 Boss 随机随从严格按定义权重抽选，不再让首项多占一个随机结果（LEG-20，冒险契约 Q4、Boss 契约 Q5）。
- 模拟战报加入玩家自己的历史，明确标为无正式成长/资产收益的模拟记录（LEG-21，冒险契约 Q3）。
- 勾选的记忆队伍在成功受理时保存；之后取消战斗仍保留配置，受理前拒绝不修改（LEG-22，冒险契约 Q5）。
- 同一 Boss 同时只受理一场挑战，忙时明确拒绝且不预留体力、不产生冷却，不排队（LEG-24，Boss 契约 Q1）。
- 满足复活条件就持久保存新轮次，不再只在页面内存中复活，跨时段不撤回复活（LEG-25，Boss 契约 Q4）。
- Boss 的差额经验基准初始化为本场实际起始 HP，修复复活首战特定检查顺序下漏发一段经验的问题（LEG-26，按明确缺陷规则修复）。
- Boss 击败时间在成功结算中记录，复活等待不回填到受理或未提交演算的时刻（LEG-27，Boss 契约 Q7）。
- 拍卖取消同 IP 限制，移动端正常竞价；卖家本人和当前最高者仍不能竞价（LEG-28，交易 Q1）。
- 商店和拍卖严格校验正整数数量，不自动补 1 或缩减，批量全部成功或失败；合法零价格保留（LEG-29，交易 Q4）。
- 竞价在写事务内检查截止，到期后不能补投；后台自动结算不依赖访问拍卖页（LEG-30，交易 Q3）。
- 上架 30 秒间隔改按账号统一判断，不再按浏览器会话（LEG-31，交易 Q5）。
- 未结卖方拍卖或最高出价义务阻止自助删号（LEG-32，交易 Q2）。
- 管理员取消未结拍卖，原子退回拍品、全部竞价款与已付上架费，不直接编辑底层状态（LEG-33，交易 Q7；承接 LEG-12）。
- 竞技全榜同时只受理一场，忙时拒绝新挑战；受理固定双方最新快照，期间不允许删改榜单，防守角色其他合法修改不影响本场（LEG-34，竞技 Q1/Q2/Q6）。
- 当前竞技名单成员必须先换出才能删除，不能绕过 48 小时登记限制形成缺员队伍（LEG-35，竞技 Q4）。
- 无效竞技对手或缺失成员导致拒绝受理，不再通过不战而胜换位或不对称记战绩；公开读取不自行清理排名（LEG-36，竞技 Q7）。
- 榜单删除后立即按剩余相对顺序补位，移除最后一人后能持久保存空榜，不留幽灵排名（LEG-38，明确缺陷修复，沿用竞技 Q6/Q7 的具名删除边界）。
