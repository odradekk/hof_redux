# 旧版重写证据清单：后台、公共信息与废弃工具

## 调查边界与分类口径

- 只读检查 `old_hof/` PHP 源码；未执行 PHP，未读取任何 `.dat` 内容、玩家目录内容或运行日志内容。
- 为确认当前选用实现，仅检查 `setting.php` 的常量声明与引用关系；本文不记录任何后台或公告编辑凭据值。
- 路径简称统一如下：本文出现的裸 `global.php` 均指 `old_hof/class/global.php`，裸 `admin.php` 均指 `old_hof/admin/admin.php`；入口包装器始终写全名 `old_hof/admin.php`。
- `正式`：有主菜单/页脚/后台菜单入口并承担实际产品或运营能力。`隐藏直达`：路由或文件可直接访问，但常规菜单没有入口或鉴权边界不完整。`备用`：与正式能力重复、明显是旧实现或辅助生成器。`废弃`：位于 `admin/gomi` 且是试算、代码生成或失效页面。`外部`：跳转项目外部站点。
- 模块采用新版约定：后台入口和公共资料归“社区与运营”；实际被管理的状态同时标注账号、交易、竞技场、世界 Boss 等所属模块。

### 原始文件编辑器的共同实现证据

`changeData()` 直接加锁、`stripcslashes()` 后覆写整个文件（`admin.php:49-58`）。它是多个正式运营入口的底层实现，但新版明确不兼容旧数据格式。源码只证明管理员可查看并整体改写这些状态，不能证明存在取消、结算、恢复、发布、审计等逐项操作。因此应先保留上表所列的管理能力边界，再逐项决定新版操作；不能以“删除通用文本框”作为这些能力已经覆盖的证明。

## 具体缺陷、冲突与待验证项

1. **后台入口与工具页鉴权断裂。** `old_hof/admin.php` 包装 `admin/admin.php` 的登录页，但 `admin/admin.php:485-491` 直接链接的所有 `list_*.php` 与 `set_action2.php` 自身都没有鉴权检查。重写验收必须从每个后台 API/页面直接访问验证拒绝，而非只测菜单隐藏。
2. **后台会话和凭据实现不应迁移。** `admin/admin.php:8-10` 将后台口令本身放进 cookie，`:540` 使用文本输入；包装器还把凭据硬编码在源码中（具体值已过滤）。新版应采用账号会话、口令哈希和最小权限。
3. **任意路径读写/删除风险。** 用户 ID、文件名直接拼路径（`admin/admin.php:93,129`），且详细页可整文件覆写；没有白名单、规范化或 CSRF 防护。重写只能暴露业务操作。
4. **公共公告页混入管理写入口。** `ShowUpDate()` 在公共 `?update` 路由接受独立口令并写文件（`global.php:747-765`），与后台公告编辑重复。应只保留统一后台写入与公共只读发布页。
5. **统计边界错误。** 账号资金平均值和角色平均值直接除计数（`admin/admin.php:198,228-235`），空服会除零；物品统计的 `if(!$data = ParseFile(...));` 末尾有空语句（`:254`），解析失败后仍进入 `foreach`。新版验收需要空数据与损坏/缺失数据场景。
6. **战报信任存储 HTML。** `ShowBattleLog()` 直接打印日志文件第 7 行之后（`global.php:475-489`）。新版结构化战报必须在展示端转义/渲染，不接受存储的任意 HTML。
7. **战报“公共”范围需确认。** 注销菜单公开战报入口（`class.main.php:3559`），包括队名、人数、平均等级和完整过程；这是代码事实，但是否继续全公开是产品/隐私待决项。
8. **怪物图鉴入口不一致。** switch 支持怪物页（`global.php:789`），页面标签和菜单却没有怪物链接（`:780-783`）。需要明确是隐藏设计还是遗漏。
9. **后台附加效果清单不完整。** 正式菜单链接的页面只以“剑”计算可能效果（`list_enchant.php:5`），不能证明所有装备类型的附加效果覆盖。
10. **图像端点调试输出类型不一致。** `ShowInfo()` 声明 `image/gif` 却调用 `imagepng()`（`image.php:155-157`），并把服务器素材路径写进图像（`:140,150`）。另背景参数没有角色参数那样的斜杠过滤（`:99-104`）；新版不应复刻该公开调试接口。
11. **旧 gomi 页面不能定义正式规则。** 多个页面保留被注释的候选公式或固定试算参数；只有与生产代码/内容定义吻合的部分可作规则线索，不能直接录入验收基线。
12. **与项目决定的关系。** 项目已明确取消“闲置自动删号”，而 `global.php:49-88` 仍有 `DeleteAbandonAccount()`，并由 `RegularControl()` 周期调用（`:90-119`）。这不在人工 ADM-USER-DELETE 的删除能力内；前者应排除，后者仍需作为正式账号管理能力决定其新版形态。

## 建议优先核验

1. 对七个原始文件编辑入口逐一决定新版允许的操作。拍卖异常处理、竞技排名修复、留言审核、账号索引修复、公告草稿/发布、不可篡改审计和日志归档都只是待决建议；旧代码仅证明这些状态可被整体查看和改写。
2. 决定战报是否仍对未登录访客完整公开，以及角色/队伍名称的展示范围。
3. 决定公共怪物图鉴、管理员怪物战术可视化编辑器是否属于首期正式能力。
4. 确认 `image.php` 静态战斗阵型图在“首期无战斗动画”的新版界面中是否仍有产品价值；战报文字/卡片能力不依赖它。
5. 明确 IP 重复审计的运营需求和隐私规则；若无明确需求，不应仅因旧代码存在而照搬。
