# 角色属性重设计

状态：已实现（2026-10-07）。本文在 `dungeon-design.md` 的基础上修改角色属性、体力、疲劳与死亡规则。数值都是首版占位，集中在 `App\Domain\Character\Attributes` 与 `App\Domain\Combat\Fatigue` 的常量中；规则页和说明书直接读取这些常量。

## 0. 背景

旧属性系统的价值几乎全部集中在单场战斗内部：旧玩法每战回满 HP/SP，没有后果。地下城把 HP、SP、体力、背包变成贯穿整次探索的消耗资源，又加入了永久死亡和非战斗房间，现有属性却基本不触及这些：

- 力量同时决定物理伤害、最大生命和背包负重，近战职业没有取舍；永久死亡下法系也只能往力量里塞点保命。
- 幸运只用于召唤物强度和战术条件，敏捷对非弓手只剩装备负重和陷阱闪避。
- 陷阱、休息、药水、事件都按最大生命的百分比结算，生命池大小在战斗外毫无意义；事件结果不看属性。
- SP 跨战斗保留，法系续航没有任何属性可以改善。
- 疲劳削减的是原始属性，而伤害按 `√属性 × 10 + 武器攻击` 计算：Lv1 战士（力量 10、短剑 10）表上 −10% 实际只少约 4% 伤害，体力为 0 的 −60% 也只少约 28%。
- HP/SP 上限公式在 `CharacterFactory`、`PlayerService::refreshVitals`、`GameRules::vital` 各写了一份。

## 1. 原则

1. **不改战斗伤害公式。** `√属性 × 10 + 攻击`、行动速率 `√速度 + 5`、防御、技能效果、怪物数据保持不变。它们同时被怪物和 268 个技能使用，改动等于重平衡全部提取内容。战斗引擎只增加两个输入：疲劳倍率（§1.6）和初始行动进度（§1.8 速度）。
2. **只重做"属性 → 派生数值"这一层**，新增价值放在探索与续航上。怪物写死了 `maxhp`，不受影响。
3. **所有派生数值由一个纯函数模块计算**（§4），战斗快照、地下城规则、角色页面、规则页都从这里取值。
4. 不兼容旧存档：迁移时退还全部已分配属性点（§3）。

## 2. 规则

### 2.1 六项属性

新增第六项 **体质**（`vit`）。界面名称沿用现有词汇：力量、智慧、敏捷、速度、幸运、体质。

| 属性 | 战斗中（不变） | 战斗外 / 地下城 |
| --- | --- | --- |
| 力量 `str` | 物理伤害 | 背包负重；**不再决定生命** |
| 智慧 `int` | 魔法伤害、治疗、最大魔力、战术行数 | **移动时恢复魔力** |
| 敏捷 `dex` | 弓类技能伤害、召唤物强度 | 装备负重（不变）、个人陷阱闪避（不变）、**队伍拆除陷阱** |
| 速度 `spd` | 行动速率 | **地下城战斗的先手 / 被伏击** |
| 幸运 `luk` | 召唤物强度 | **侦察迷雾、宝箱额外掉落、事件好结果权重** |
| 体质 `vit` | —（通过生命上限间接生效） | **最大生命、体力上限与回复、濒死坚持步数** |

战术条件 1300–1381 仍只比较原五项与攻防；本次不新增体质条件。装备、技能与附魔中没有体质加成，以后可在手工内容中加入。

### 2.2 成长

- 每升一级获得 **5** 点属性点（原 3 点），技能点仍为 1 点。Lv50 共获得 245 点。
- **取消单项属性上限**（原 255）。分配时只检查非负整数且不超过剩余点数。
- 等级上限 50、经验表、单次最多升一级并舍弃溢出经验的规则不变。
- 属性重置道具 7510–7513 的下限 1 / 30 / 50 / 100 作用于全部六项，含体质。
- 战术行数表在智慧 200 以上保持最高档，规则页显示为"200 以上"。

### 2.3 派生数值

设等级系数 `L = 1 + (等级 − 1) ÷ 49`（与旧版相同，Lv1 为 1，Lv50 为 2）。

| 数值 | 公式 |
| --- | --- |
| 最大生命 | `round(100 × 职业生命系数 × L × (1 + 体质 ÷ 100))` |
| 最大魔力 | `round(100 × 职业魔力系数 × L × (1 + 智慧 ÷ 100))` |
| 体力上限 | `100 + 体质` |
| 城镇体力回复 | 每天 `5 × 体力上限` 点（即每秒 `5 × 体力上限` 单位，任何体质下约 4.8 小时回满） |
| 濒死坚持步数 | `3 + floor(体质 ÷ 20)` |
| 移动魔力回复 | 每次移动恢复 `floor(floor(√智慧) ÷ 2)`% 最大魔力 |
| 背包负重 | `10 + floor(力量 ÷ 10)`（不变） |
| 装备负重 | `5 + floor(等级 ÷ 10) + floor(敏捷 ÷ 5)`（不变） |
| 个人陷阱闪避 | `min(50, floor(敏捷 ÷ 4))`%（不变） |
| 队伍拆除陷阱 | `min(50, floor(队伍最高敏捷 ÷ 5))`% |
| 侦察 | `min(80, 20 + floor(队伍最高幸运 ÷ 2))`% |
| 宝箱额外掉落 | `min(50, floor(队伍最高幸运 ÷ 3))`% |
| 事件好结果权重 | `floor(权重 × (100 + 队伍最高幸运) ÷ 100)` |
| 先手 / 被伏击 | 双方平均行动速率之比 ≥ 1.25 |

生命和魔力改为线性：每点体质或智慧都是 +1% 基础值，没有上限也不会像旧公式那样超过 255 后反而下降。装备与被动技能的 `P_MAXHP`、`M_MAXHP` 等加成照旧叠加在结果上。

"队伍最高"只计算可行动的成员（不含濒死者）。

### 2.4 初始体质

提取的 `base_characters` 保持原样，初始体质作为常量按基础类型给出，其余初始属性不变。数值按 Lv1 生命与旧版接近来取：

| 基础类型 | 职业系数（生命 / 魔力） | 初始体质 | Lv1 生命（旧） | Lv1 魔力（旧） |
| --- | --- | --- | --- | --- |
| 1 战士 | 3 / 0.5 | 8 | 324（323） | 51（51） |
| 2 巫师 | 1.5 / 1 | 3 | 155（152） | 110（108） |
| 3 牧师 | 2 / 0.8 | 4 | 208（205） | 86（85） |
| 4 猎人 | 2.2 / 0.7 | 5 | 231（223） | 71（71） |

Lv50 参考：战士体质 100 时生命 1,200；狂战士（系数 5）体质 150 时 2,500。旧版上限分别为 1,200 与 2,000。

### 2.5 体力

- 上限 `100 + 体质`，不低于 100，所以打工（固定消耗 100、获得 500）和共享首领（10）的消耗不变。
- 城镇回复速度随上限成比例增长，回满时间恒定约 4.8 小时；地下城中仍不自然回复。
- 干粮、休息处、事件的体力恢复仍为固定点数，不超过上限。
- 体质变化（分配、重置）前，先按旧上限和旧速度结算城镇回复，再应用新上限；当前体力超过新上限时截断。生命和魔力同理（`refreshVitals` 前先 `settle`）。
- 经济影响：每名角色每天可打工的次数随体质线性增长（体质 100 时为 2 倍）。若需要限制，可另设每日打工次数，本稿不处理。

### 2.6 疲劳

疲劳档位改为按 **体力占上限的百分比** 划分，并直接作用在战斗结果上，不再削减原始属性：

| 体力 ÷ 上限 | 造成的伤害与治疗 | 行动速率 |
| --- | --- | --- |
| ≥ 60% | 不变 | 不变 |
| 30%–59% | −10% | −5% |
| 10%–29% | −20% | −10% |
| 大于 0 且低于 10% | −35% | −20% |
| 0 | −50% | −30% |

- 伤害倍率作用于 `basicDamage` 与 `healing` 的结果（包括 10% 保底伤害；复活技能的回复量也走 `healing`），行动速率倍率作用于 `Combatant::rate()`。按最大生命百分比结算的技能（如献祭、惩罚）、中毒伤害和召唤物不受影响。
- 快照字段 `fatigue` 由整数百分比改为 `{output, speed}`；怪物和不使用疲劳的模式没有该字段，倍率为 1。
- 使用范围不变：地下城战斗和共享首领使用；竞技场和模拟战不使用。
- 角色页的体力一行与探索页的队伍卡片显示当前的两个减少比例。

### 2.7 濒死

只存在于地下城探索中。

**进入濒死。** 角色在地下城中生命降到 0（战斗结束时倒下、陷阱、事件）时，不立即死亡，而是进入濒死，获得 `3 + floor(体质 ÷ 20)` 步坚持步数。

**濒死期间：**

- 生命为 0，不能行动，由同伴带着走。
- 不消耗体力，不受陷阱和事件的伤害与体力效果，不参与移动魔力回复，不计入"队伍最高"判定和"敌人数量 = 出战人数"。
- 玩家每执行一次移动，每名濒死成员坚持步数 −1，先扣再结算新房间；归零即永久死亡（沿用现有死亡流程：写入 `died_at`、装备转入战利品）。战斗失败被迫退回上一个房间不扣步数。
- 进入战斗时以倒下状态（生命 0、`state = 1`）站在原位置。敌人不会以倒下单位为目标，己方的复活技能（3040 复苏、5030 灵魂复苏、5063 清醒）可以把他们救起。

**救回。** 以下任一方式使濒死成员生命大于 0，即为救回，生命为恢复量（至少 1）：

- 对其使用恢复生命的消耗品（`use` 允许以濒死成员为目标，但只接受带 `restore.hp` 的道具）；
- 休息处或事件的生命恢复效果；
- 战斗中被复活，战斗结束时生命大于 0。判定只看战斗结束时的状态：同一场战斗中被复活又再次倒下的成员仍是濒死，步数不变。

**重伤。** 被救回的角色在本次探索余下时间内处于重伤：生命再次降到 0 时直接死亡，不再进入濒死。每名角色每次探索只有一次濒死机会。

**全灭。** 没有任何可行动成员时探索以 `wiped` 结束，所有濒死成员一同死亡，背包和战利品照旧遗失。

**离开。** 从出口离开或撤离时，濒死成员随队返回城镇，生命设为 1，开始城镇回复；重伤与濒死状态随探索结束清除。

竞技场、模拟战、共享首领不造成持久伤害，与濒死无关。

### 2.8 探索判定

单人承受的效果逐人判定，侦察、拆除这类"有一个人会就行"的判定取队伍最高值。所有随机结果使用该操作的服务器种子，结果随操作保存，重放得到同一结果。

- **智慧：移动魔力回复。** 每次移动后，每名可行动成员恢复 `floor(floor(√智慧) ÷ 2)`% 最大魔力（智慧 4 起 1%，100 为 5%，196 为 7%）。不受疲劳影响。
- **敏捷：拆除陷阱。** 进入陷阱房间时先由敏捷最高的可行动成员（并列时取角色 ID 较小者）判定拆除；拆除成功则无人受伤、也不扣陷阱的体力，房间清空。失败后每名成员再按自己的敏捷判定闪避（不变）；陷阱的体力损失仍对全员生效（不变）。
- **速度：先手与被伏击。** 进入战斗房间时，比较双方平均行动速率（我方为可行动成员、已计入疲劳）。一方达到另一方的 1.25 倍时，该方所有单位以初始行动进度 50 开战（满 100 行动）。确定性判定，不使用随机数。只用于地下城战斗。
- **幸运：侦察。** 房间第一次出现在迷雾边缘（与到过的房间相邻）时，按队伍最高幸运判定一次，成功则显示该房间的名称和类型。结果保存在探索记录的房间状态中（`scouted`），不会重新判定。进入地下城时对入口的相邻房间同样判定。
- **幸运：宝箱。** 开宝箱时按队伍最高幸运判定一次，成功则多抽一次 `loot`。
- **幸运：事件。** 事件结果可标记 `"lucky": true`；结算时这些结果的权重乘以 `(100 + 队伍最高幸运) ÷ 100`（向下取整），其他结果权重不变。

### 2.9 陷阱与事件伤害改为固定值

为了让生命池和体质在战斗外也有意义，陷阱房间与事件的伤害改为固定点数；恢复类效果仍按百分比。

| 位置 | 旧字段 | 新字段 | 新值 |
| --- | --- | --- | --- |
| 哥布林小径 · 隐藏的陷坑 | `damage_percent: [10, 20]` | `damage: [低, 高]` | `[30, 60]` |
| 古之洞穴 · 湿滑的斜坡 | `[15, 30]` | `damage` | `[80, 160]` |
| 滴冻山 · 冰隙 | `[20, 35]` | `damage` | `[100, 200]` |
| 哥布林小径 · 旅人（查看伤口） | 事件 `damage_percent: 15` | 事件 `damage` | `40` |
| 古之洞穴 · 水洼（喝几口） | `10` | `damage` | `50` |
| 古之洞穴 · 神龛（祈祷） | `20` | `damage` | `100` |
| 滴冻山 · 暴风雪（挖雪洞） | `15` | `damage` | `80` |

同时为以下事件结果标记 `lucky`：旅人"查看伤口"的体力 +10，水洼的魔力 +30%，神龛的生命 +40% 与体力 +20，暴风雪"挖雪洞"的恢复结果。

### 2.10 不变的部分

战斗伤害、防御、命中（无命中判定）、技能、召唤、怪物、装备、精炼、附魔、战术条件、经验表、城镇生命/魔力每小时 20% 回复、背包与战利品规则、共享首领与竞技场规则。

## 3. 内容、数据与迁移

### 3.1 内容

- `content/redux/dungeons.json`：陷阱房间 `damage_percent` 改为 `damage`；事件效果 `damage_percent` 改为 `damage`；事件结果可选 `lucky: true`。修改后运行 `python3 tools/content/authored.py`。
- `DungeonMap` 校验：`damage` 为非负整数区间或非负整数；`lucky` 为布尔值；效果封闭列表改为 `heal_percent`、`damage`、`sp_percent`、`stamina`、`money`、`item`。

### 3.2 数据

- `characters.stats` 增加 `vit`。
- `characters_stamina_bounds` 改为 `stamina_units >= 0`；上限由代码按体质保证。
- `dungeon_runs` 增加 `members`（JSON，可为空，空值视为没有状态），按角色 ID 保存 `{"dying": 剩余步数}` 或 `{"wounded": true}`；探索结束时清空。房间状态增加 `scouted`（布尔值，每个房间只判定一次）。

### 3.3 迁移

一次性迁移，不保留旧分配：

1. 先放宽 `characters_stamina_bounds`（否则回满到 100 以上的体力会违反旧约束），再处理每名角色：写入初始体质（§2.4），力量、智慧、敏捷、速度、幸运恢复为基础类型的初始值。
2. `stat_points = 5 × (等级 − 1)`：退还全部已分配点数，并按新的每级 5 点追溯发放。
3. 按新公式重算最大生命与魔力；当前生命、魔力、体力全部回满，时间戳设为迁移时刻。已死亡角色只补体质与上限，生命保持 0。迁移内写出数值而不引用 `Attributes`，规则以后调整时迁移的含义不变。
4. 进行中的探索保留，所有成员视为可行动、无重伤。
5. `down()`：移除 `vit` 与 `members`，五项属性恢复初始值并按每级 3 点发放，体力截断到 100 并恢复原约束。

```

app/Domain/Combat/Fatigue.php          按体力比例给出 {output, speed} 倍率
app/Domain/Combat/Combatant.php        读取快照的 fatigue 与初始 progress
app/Domain/Combat/Effects.php          basicDamage / healing 乘以 output 倍率
app/Domain/Dungeon/RoomRules.php       拆除、固定伤害、侦察、宝箱额外掉落、幸运权重
app/Application/Player/PlayerRules.php 每级 5 点；STATS 加入 vit

app/Application/Player/Vitals.php      体力上限与回复速度按体质计算
app/Application/Dungeon/DungeonService.php  濒死、重伤、移动魔力回复、拆除、侦察、先手、全灭判定
app/Application/Battle/BattleService.php    濒死成员以倒下状态入场；先手进度；新疲劳
app/Services/CharacterFactory.php      初始体质；生命与魔力改用 Attributes
app/Application/World/GameRules.php    删除 STAT_CAP 与 vital()，规则页从 Attributes 取数
app/Http/View/DungeonMapView.php       显示已侦察房间的类型
resources/views/...                    角色页六项属性与派生数值、地下城濒死 / 重伤状态与坚持步数、规则页与说明书
database/migrations/...                §3.2、§3.3
```

`Attributes` 与战斗引擎一样不依赖 HTTP、数据库、时钟或全局随机数：输入为属性、等级、职业系数，随机判定由调用方传入随机流。

实现时的补充：

- 等级、职业或属性变化前（加点、重置、转职、战斗升级），休息中的角色先按旧上限结算城镇回复（`Vitals::settleIfResting`），再重算上限；当前生命、魔力、体力只截断、不补满。
- `CharacterFactory` 显式写入等级 1，新建角色在重新读取前也能正确计算上限。

## 5. 验证

已运行（PHP 8.4.11 容器，SQLite 与 PostgreSQL 18.6）：

- SQLite 全部测试：258 通过，16 个仅限 PostgreSQL 的测试跳过。PostgreSQL 全部测试：274 通过。Laravel Pint 无剩余问题。

## 6. 风险与待定

- **竞技场平衡。** 线性生命和魔力且无上限，后期纯体质或纯智慧角色的生命、魔力会超过旧版上限（单项属性约 250 时为旧上限的约 1.8 倍），竞技场的生存数判定可能偏向坦克。尚未用代表性配点做模拟对比；如有需要，只调整 `Attributes` 中的系数。
- **打工收入**随体质增长（§2.5）。
- **地下城数值**（陷阱固定伤害、坚持步数、先手阈值）需要在实际探索中再调。
- 体质暂无装备或技能来源，也没有对应的战术条件。
