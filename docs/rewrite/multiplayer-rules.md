# Multiplayer rules and consistency

Source: retained `class.auction.php`, `class.rank2.php`, `class.union.php`, relevant handlers in `class.main.php`, content cases 2000–2011. No legacy code is executed.

- Auction enabled as requested. Membership card 9000 costs 11,000. Listing fee 500; allowed source item types only; one to twenty-four hours from explicit duration list; global 100 active listings; per-account 30-second listing interval survives session changes. No cancellation endpoint: source has none. Unsold item returns to seller without fee refund. Minimum bid is current price plus max(100, floor(10%)). Current highest bidder and seller cannot bid. A bid within the final fifteen minutes extends to fifteen minutes from that bid. The legacy IP/mobile bans are removed: they are not ownership/authentication checks and block legitimate shared-network users.
- Escrow is represented by an inventory row at `auction` and the listing's escrow money. Outbid funds return in the same transaction as the new bid. Sold/unsold terminal records remain history; expiry and maintenance use the same settlement. No uncommitted reward is externally visible.
- Ranking uses a total slot order packed into place capacities 1,2,3,3,... exactly as active rank2. Teams can change once every 48 hours. Entrants join the bottom and challenge a seeded random member one place higher, except the first entrant establishes the ladder. Winner swaps slots; win cooldown 60 seconds, loss/draw 24 hours. Missing defense party grants a walkover with no challenger win credit as source; defender loss is recorded. Deleted accounts disappear and slots repack. PvP uses the corrected survivor-count rule in the combat engine and never persists injuries, XP or loot.
- Fresh worlds explicitly initialize one instance of each source union boss 2000–2011. This is a fresh roster decision grounded in all twelve source definitions, not reconstruction of missing runtime files. Population-scaled HP/reward, effective cycle and content version are snapshotted at each spawn. Time-dependent cycle rules for 2004–2007 resolve in UTC at spawn. Respawn at the exact deadline is allowed, fixing the old strict-inequality boundary. Each boss has shared HP/SP, per-account global twenty-minute cooldown, ten stamina cost, source party-level ceiling and source minions. A unique `(boss,generation)` kill constraint prevents duplicate final rewards.
- All gameplay mutations currently serialize behind PostgreSQL transaction advisory lock 72641001 before row locks. This is deliberate first-release simplicity and a throughput limit, not a scalability claim. Transactions have bounded retries; operation IDs bind request payload and committed result. Random seed is generated outside retry closure, so internal retries preserve randomness.
- Maintenance: `php artisan game:maintain --bootstrap` on fresh installation; `game:maintain` each minute thereafter. Both maintenance and request settlement are idempotent. A missing scheduler does not prevent request-triggered auction settlement or boss respawn.
