# 账号生命周期与会话契约

状态：已确认。Q1–Q13 及 Q14 完整契约均经用户确认。对应[确定账号生命周期与会话契约](https://github.com/odradekk/hof_redux/issues/12)。本文件是规划，不表示账号系统或安全验证已经实现。

前置：[状态与事务](state-transactions.md)、[交易](trading.md)、[竞技场](arena.md)、[世界 Boss](world-boss.md)、[内容模型](content-model.md)及[保真基准](../legacy/fidelity-decisions.md)。无邮件、无闲置自动删号、不迁移旧账号；保留密码登录，新增经批准的恢复码与具名账号管理。

## 已确认裁决

| 问题 | 裁决 |
| --- | --- |
| Q1 找回密码 | 注册发放由玩家保存的恢复码；登录名加恢复码可重置密码，成功后轮换恢复码并撤销全部旧会话。服务端不保存可直接读出的恢复码；密码和码都丢失不承诺找回 |
| Q2 多设备 | 允许手机、电脑同时登录，不绑定 IP；退出当前设备与退出全部设备分开。修改或重置密码撤销所有旧会话，包含当前会话，要求重新登录 |
| Q3 玩家会话 | 闲置 7 天、登录起最多 30 天；服务端判断，可作部署配置，不影响已受理业务 |
| Q4 密码 | 15–128 个字符，允许中文、空格、符号和粘贴，不强制字符组合；不裁剪首尾空格，不无故定期改密，拒绝常见及已知泄露的弱密码 |
| Q5 名称 | 登录名 4–16 位 ASCII 字母或数字，大小写不敏感、注册后不可修改；队伍名及角色名 1–16 个字符，中文一字计一，统一等价 Unicode，去首尾空白、拒绝换行及不可见控制字符。队名全服唯一且区分大小写，角色名可重复；改队名仍付 100,000 金钱 |
| Q6 名称复用 | 登录名和旧队伍名均允许释放后复用；内部身份永不复用，历史仍属于原身份 |
| Q7 自助删号 | 展示影响、输入当前密码并明确确认；满足条件后立即删除，无反悔期。清除可玩进度、凭据和会话，释放名称，只保留历史与审计所需的已删除身份记录 |
| Q8 解雇 | 同一事务内把穿戴装备的原实例退回背包、清理引用并删除角色；不绕过竞技名单和战斗占用保护 |
| Q9 零角色 | 保留允许零角色的旧行为，可通过打工和招募恢复；不额外赠送角色或初始资源 |
| Q10 停用 | 管理员可停用/恢复账号并记录原因；停用撤销会话、阻止新的玩家操作，已受理战斗和拍卖正常处理，既有竞技防守仍可被挑战。停用不删除、不释放名称、不自动清理业务 |
| Q11 管理员身份 | 独立具名身份，首期一种管理权限；无游戏资产、不计玩家数，仅服务器管理者可创建或撤销，玩家生命周期不影响管理员 |
| Q12 管理员登录 | 首期只用密码，不引入 TOTP 或其他第二因素；不使用玩家恢复码找回管理员身份 |
| Q13 管理员会话 | 闲置 15 分钟、最长 8 小时；敏感操作要求最近 5 分钟内完成密码验证，超时重新验证，破坏性操作仍展示对象和影响并确认 |

以下将裁决落实为操作边界、失败处理和验收场景；恢复码重新签发等衔接细节已随 Q14 完整契约确认，不属于旧版能力。

## 身份与名称

账号模块持有稳定内部身份、登录名、凭据、会话、停用状态及首次建队状态。资产、角色、竞技、拍卖和战报由各自模块持有，并引用内部账号身份。登录名和队伍名是可复用名称，不能作为数据库外键、幂等命名空间或历史归属的依据；管理员使用独立身份空间。

登录名先按 ASCII 规则校验，再转小写作为唯一键，大小写写法指向同一账号。队伍名和角色名采用 NFC 规范化，按 Unicode 码点计数，不按 UTF-8 字节或 JavaScript UTF-16 单元计数；组合 emoji 可能占多个码点。先拒绝换行、控制及不可见格式控制字符，再裁剪首尾空白并校验长度。密码不套用名称规范化或裁剪规则，按输入的有效 Unicode 原文验证，长度同样按码点计数。

队伍名按规范化后的文本精确唯一，不折叠大小写；角色名不设全服或账号内唯一约束。存储原始规范化名称，在展示时转义，不将 HTML 转义后的字符串作为名称身份。名称检查与占用在同一事务完成，不能依赖页面预检查。

账号删除后释放登录名和队伍名，改队名后释放原队名。历史保存事件发生时的名称及原内部身份；另一个人复用名称不会承接战绩、交易、留言所有权、恢复码、会话或请求结果。对已删除身份明确标记，历史可见范围和保留期限交展示、运营及运行专题确定，不用删号级联抹除他人的成交记录。

## 注册、首次建队与零角色

保留“注册账号 → 登录后首次建队”的两步业务。注册事务创建账号与唯一登录名、密码及恢复码摘要、首次建队待完成状态，并通过资产模块一次发放旧初始金钱 10,000 和体力 100；不通过文件夹存在与否推断完成状态。注册成功展示一次恢复码，要求玩家自行保存。注册失败不能留半个账号或部分初始资产，重复同一次注册不再次发放。

旧 `MAX_USERS=500` 保留为可配置注册容量的默认值；计入已创建且未删除的玩家账号，包含未完成建队、不活跃及停用账号，排除管理员和已删除身份记录。它与约 100 人在线负载目标不同。容量及登录名并发争用在注册事务内校验；删除释放容量，无闲置或未建队自动删除。

首次建队一次提交队名占用、首名角色及其初始装备实例、建队完成标志。保留旧战士/法师与男女组合的四种选择，初始数值与装备来自迁移后的招募模板；非法选择拒绝，不沿用旧默认落入女法师的隐式转换。待完成账号可登录、管理自身凭据或删号，正式玩法先完成建队。世界 Boss 玩家总数仍按账号已创建且未删除计算，不以首次建队作为计数门槛。

建队完成状态与角色数量独立。解雇到零人后仍是已完成账号，不再次开放免费首角或重发初始资产；界面可进入打工、招募和其他不要求角色的合法功能，出战明确提示缺少角色。体力按原规则恢复，打工与招募不要求已有角色。竞技名单仍需 1–5 人且当前成员不能直接删除：允许零角色不解除这项引用保护。

## 登录、会话与凭据修改

使用服务端可撤销的不透明会话，不在浏览器保存密码。玩家每次成功登录建立自己的会话，其他设备不被挤下线；普通退出撤销当前会话，退出全部设备撤销账号当时全部会话。服务端存储会话令牌摘要及身份、创建时间、最后活动时间和验证时间，客户端仅持随机令牌。后台战斗结算、拍卖和定时任务不续期；自动轮询不作为玩家活动来续期，前端明确用户发起的有效请求才更新活动时间，不信任客户端提供的时间。

闲置期限和绝对期限任一到达即失效，包含等于边界。活动不延长绝对期限，普通重新验证不刷新会话创建时间；到期重新登录才建立新会话。管理员使用单独的会话作用域，玩家会话不能调用管理接口。7 天/30 天为本项目便利性取舍，并非外部安全指南推荐的统一时长；服务端同时实施闲置和绝对期限依据 [OWASP 会话指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

| 操作 | 身份证明及原子结果 |
| --- | --- |
| 正常改密 | 有效玩家会话及当前密码；更新密码并撤销全部旧会话，要求重新登录。原恢复码继续有效，玩家可另行重新签发 |
| 忘记密码 | 登录名及当前恢复码；更新密码、消耗旧码、保存新码摘要、撤销全部旧会话，一次提交；不自动登录 |
| 重新签发恢复码 | 有效玩家会话及当前密码；旧码作废，生成新码并仅展示一次。不产生游戏收益或新的身份找回渠道 |
| 当前退出/全部退出 | 撤销对应会话；重复执行无额外作用。退出不取消已受理业务 |

恢复码使用至少 128 位不可预测随机量，凭据绑定内部账号身份，服务端只保存摘要，不放进 URL、业务流水、普通幂等响应缓存或日志。使用后失效，不因账号长期不活跃而定期轮换；丢失恢复码但仍知密码时可登录后重新签发。恢复码只用于重置，不是可直接登录或购买物品的令牌。离线保存及一次性使用依据 [OWASP 密码找回指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

恢复码明文只在成功注册、重置或重新签发的当次响应展示。若响应丢失，不重放或保存明文；玩家使用刚设置的密码登录，再凭密码重新签发。注册或重置的网络超时显示“结果待确认”，不能断言失败；原恢复码已消费后的重试不得再更改密码。正常改密响应丢失也可用新密码重新登录。客户端不在浏览器日志或长期存储中保存恢复码。

账号停用后拒绝新的玩家命令，包含登录、自助重置密码及重新签发恢复码，不允许使用旧会话操作；管理员恢复账号后才可重新登录或使用原有效恢复码，已撤销会话不复活。已删除账号全部凭据失效，旧码不适用于复用登录名的新账号。不使用队名、IP、游戏进度或客服猜测身份代替密码/恢复码。

密码采用 Argon2id 与独立随机盐；至少采用 19 MiB 内存、2 次迭代、并行度 1 的基线，部署前评估成本与并发容量，具体库在接口与运行方案选型。不能用快速哈希替代密码哈希；高熵随机会话/恢复令牌可以使用安全摘要。参数依据 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。

所有设置密码的入口采用 Q4 同一规则，本地版本化弱密码/泄露密码列表参与校验，不发送用户密码给第三方。登录失败对未知名称与错误凭据返回一致说明；登录、恢复和注册实施按来源与目标结合的限流，密码计算并发有界，具体阈值由运行专题结合负载验证，不以共享出口 IP 为由禁止正常多玩家。长口令、允许粘贴与弱密码拦截依据 [OWASP 身份验证指南](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

## 改名、解雇与删号

改队名在一个事务中校验目标名称唯一、余额与请求身份，扣除 100,000 金钱、切换名称并释放旧名；失败全不变，同一请求重试不再扣费。规范化后与当前队名相同则拒绝无变化请求，不扣费。角色改名保留每次合法新请求消耗道具 7500 一件，通过角色与资产模块一次完成，同一请求重试不再消耗；界面避免提交无变化的角色名，但不借此修改旧道具收费规则。改名不回写历史快照。

解雇前展示角色成长、技能等会消失，穿戴装备会退回背包。事务内检查所属账号、角色存在、竞技名单引用、出战角色/装备占用及依赖版本；允许删除最后一人。把原装备实例移到背包，保留精炼和附加效果，删除角色及仅属于其自身的成长/战术配置，清理记忆队伍等实时引用并写操作结果。角色删除不删除已有战报中的快照身份；不能把穿戴装备复制一份或遗漏原位置。

自助删号先展示将清除的角色、背包、金钱、体力及个人配置，再以有效会话、当前密码和明确确认提交。最终写事务重新检查以下条件，不以预览结果代替校验：

- 自己无未终结的正式战斗、模拟战或其他待处理操作，无业务占用/资源预留；与并发受理互斥。
- 无未结卖方拍卖，且不是任何未结拍卖的最高出价者；超价退款已成功完成后不再受该笔阻止，历史交易不阻止。
- 若在竞技榜内，全榜不存在未终结挑战；即使本人不是该场双方，也不能因删除重排榜单。榜外且无其他占用者不受这条限制。

通过后，在单一事务中删除可玩进度与实时引用、移出竞技榜并按原顺序补位、释放名称和容量、撤销会话及恢复码/密码凭据、记录最小已删除身份与操作结果。删除整个账号不要求逐个将竞技角色换出，也不等待 48 小时重新登记；它按整号删除的榜单/义务规则处理。不得通过级联删除毁掉他人的交易权益。任一步失败全部回滚，不静默取消战斗、撤拍或退款。

删除命令幂等键绑定原内部身份，旧会话或旧请求永远不能删除同名新账号。为处理成功删除后响应丢失，提交前由客户端生成并保留高熵删除回执令牌，服务端在删除事务中保存摘要及该次删除结果；仅凭该令牌可查询“本次已删除/尚无完成记录”，不返回账号资料或允许新操作。无完成记录不等于可证明失败，仍有效时通过原请求重试。短期回执保留期限由运行专题确定；过期后提示结果不可查询，不复活原身份或重放删除。

## 管理员与停用

管理员独立具名，首期统一管理权限，不实现自定义角色体系。服务器管理者通过受控本机管理命令创建、撤销、重置管理员密码；所有这些动作均留记录，不设公开注册管理员入口、共享默认密码或玩家找回绕过。管理员密码采用同一长口令和存储规则；首期只有密码，敏感操作重新验证也只验证密码。

管理员会话闲置满 15 分钟或自登录满 8 小时即失效。删除账号、资产修正、拍卖取消退款等敏感操作，必须在服务端最终提交时检查距最近成功密码验证未超过 5 分钟；超过则重新验证，普通浏览活动不刷新这个时间。管理员改密、服务端重置或撤销身份使其所有旧管理会话失效；撤销管理员身份不得使历史审计变成无主记录。

停用/恢复必须校验管理权限、目标身份与版本、必填原因；记录管理员、目标、时刻、前后状态及结果。停用与会话撤销一次提交，恢复不恢复会话；重复请求不重复产生状态转移。停用只阻止未来玩家命令：已受理战斗继续结算，拍卖可以退款或交付，竞技仍允许将该账号作为守方，世界 Boss 的玩家计数仍包含它。

因此旧契约中的“账号生命周期/账号有效”检查要区分“允许发起新操作”与“原身份仍存在且能承接既有业务”：停用不构成故障取消理由，停用时不改战斗依赖版本、不清空角色或资产。已受理操作的内部执行者不依赖玩家当前会话；停用先提交则新的玩家操作拒绝，业务受理先提交则按原契约完成。

管理员删除账号也遵守未结业务和全榜占用保护；需要清理时先分别执行已有的具名取消、退款或移榜操作，不提供跳过校验的“强制删除”。完整管理操作目录、日志查询和具体敏感操作清单由运营专题完成，本专题提供统一身份、再次验证及生命周期门槛。

## 事务与认证并发

密码哈希计算、密码校验和耗时工作在 SQLite 写事务之外。验证开始时固定内部身份及凭据版本；取得写事务后复核同一内部身份、凭据版本、会话撤销/到期状态和业务资格。验证过程中发生改密、恢复、停用、删除或名称复用时，不能仅按登录名重新解析后给另一个身份创建会话或改密。

登录签发会话、恢复码消费及重新签发、密码更新和会话撤销分别以短事务完成。两次恢复并发只有一个可消费原码；恢复与正常改密并发后，旧密码计算结果不能签发漏撤销的会话。账号写命令提交前检查会话是否仍有效，不能在中间件通过一次后无限沿用；已经受理的战斗则按持久操作身份继续执行。

管理命令同时校验管理员资格、会话与近期验证，再由目标模块完成业务；停用、删号、交易或挑战并发时由事务顺序决定哪一个先成功。不存在“先删除后后台仍向旧完整账号快照保存”的路径。

注册和找回属于未登录入口，另设请求幂等身份；缓存只存安全状态及原身份引用，不存密码、恢复码或会话令牌明文，也不以未登录的用户名查询公开完整账号状态。密码不进入请求日志、URL、错误详情或审计。生产使用 HTTPS、HttpOnly/Secure 会话 Cookie，明确 SameSite 与 CSRF/Origin 校验；所有状态修改不用 GET。HTTP 错误码、Cookie 名称及代理配置由接口/运行专题细化。

## 验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 同时注册大小写不同的同一登录名，或争最后注册名额 | 仅一笔成功，失败方无账号/资产；重试不重发初始资源 |
