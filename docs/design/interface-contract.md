# 接口契约与客户端状态同步

状态：已确认。Q1–Q6 逐项决定及 Q7 完整契约均经用户确认。对应[确定接口契约与客户端状态同步](https://github.com/odradekk/hof_redux/issues/16)。这是接口与客户端行为的规划基线，不表示接口已经实现或通过运行验收。

## 已确认的客户端行为

| 决定 | 行为与取舍 |
| --- | --- |
| Q1 前台定时查询 | 首期不做服务器实时推送。页面可见时按业务定时查询，战斗处理中更频繁，拍卖、Boss、竞技排行分别安排；隐藏页面暂停定时查询，切回页面或网络恢复时立即查询。界面显示更新时间，允许其他玩家的变化晚几秒显示；具体间隔结合 100 人负载验收确定 |
| Q2 写请求超时 | 购买、竞价、出战等发生网络超时后只自动查询原操作，不自动重发写请求。暂时查不到记录不能断言失败，保持结果待确认；玩家主动重试时复用原请求身份和参数，不能自动换身份另开一笔 |
| Q3 普通会话到期 | 重新登录同一内部账号身份后返回原页面，保留当前页面内存中尚未丢失的战术草稿；先读取最新状态，冲突时保留草稿供核对，不自动提交到期前动作。切换账号清除原账号草稿与私有页面数据；刷新/关闭可能丢失草稿，灾难恢复继续按既定流程重新登录、刷新并核对 |
| Q4 发布后旧页面 | 检测到应用或内容版本改变，提示更新并暂停新写操作；服务端拒绝旧版本新操作。不强制刷新，允许查看并复制内存中未保存战术后手动刷新。已受理业务继续按原约定处理 |
| Q5 刷新后的查询线索 | 当前标签页的会话存储只保留普通游戏操作的查询标识、原内部账号身份及恢复代次，刷新后仅用于查询。不保存请求正文、密码、恢复码或战术草稿，不自动重发；切换账号/恢复代次变化清除，关闭标签页后不承诺保留 |
| Q6 结束本次核对 | 玩家可手动要求服务器检查原操作；已受理则返回原状态，尚未受理则原子封闭该请求身份，迟到请求也不能执行。收到封闭确认后才能按当前状态重新填写并提交；封闭请求超时仍继续查询，不取消已受理业务 |

定时查询和恢复前台后的自动查询不作为玩家活动延长会话闲置期限，沿用[账号契约](accounts.md)。页面显示的新鲜度不等于交易、出战或到期资格；各写操作继续在已确认的服务器业务时点校验。

## 沿用的前置约束

- [状态与事务](state-transactions.md)：一次业务通过所属模块的具名操作执行，HTTP 入口不自行拼接扣款、加物和结算。相同请求身份及参数返回原操作状态/结果，同一身份换参数拒绝；读取旧结果仍需鉴权。
- [手机交互](mobile-interaction.md)：草稿与已保存配置分开，旧配置冲突不能自动换新版本重发。正式战/模拟分别显示受理、处理中、未知、人工处理及终态；页面离开不取消已受理业务。
- [账号](accounts.md)与[运行](runtime.md)：服务端可撤销会话、普通和管理身份隔离、恢复代次隔离、敏感信息不进入 URL/普通日志/幂等结果缓存。注册、改密、恢复和删除回执遵守各自已确认的特殊规则，不直接套用普通游戏结果重放。
- [展示](public-information.md)：正式战报公开、模拟私有；查询须按身份与权限投影，不向客户端发送完整战术、随机输入或内部复现材料。未授权者不能通过过期/清理提示探测私有记录。
- [战斗](combat-contract.md)：历史展示读取保存的结构化事件及显示状态，不为翻页重新演算。步骤与事件归属、单次实际变化和 HP/SP 净变化分开；原型逐步快照不规定生产存储形式。
- [内容发布](content-release.md)：应用、内容和规则版本对应一致，发布必须保护在途业务及现有数据；当前资料由公开投影提供，不把完整内部内容包发送给浏览器。

## 接口形式与模块职责

首期采用同源 HTTP JSON 接口，路径置于 `/api/`；服务于本项目网页和管理后台，不额外承诺第三方长期兼容或提供开放平台。页面读操作与具名业务命令分开，普通查询使用 GET，修改状态的玩家/管理员命令使用 POST，不通过 GET 购买、竞价、改配置或触发管理操作。鉴权状态与需要复核的版本由服务器确定；客户端提交身份字段只用于核对上下文，不作为授权依据。

模块之间直接调用 TypeScript 操作，不绕行 HTTP。事务设施由最外层业务操作控制，接口处理器只完成协议解析、身份与上下文传递、调用及结果映射；不能拆成若干 HTTP 请求分别扣款、发物或保存角色。共享查询可以组合模块公开读取，但无权直接修改其他模块数据。

世界 Boss 的访问时复活检查沿用已确认规则：页面查看时通过具名 POST 请求执行统一的按规则检查并返回已提交状态，纯 GET 只读取已提交状态。这个系统检查允许重复调用，每轮最多复活一次；不属于重新提交玩家挑战，调用者不能指定轮次、HP 或复活时间。遵守来源校验、访问权限和限流，自动检查不续会话；维护或保护性暂停期间不执行转换，页面仍可只读查询。定时任务和挑战入口调用同一模块操作，其他查询不顺便执行玩家命令、修复榜单、预抽遭遇或发放收益。

## 共享定义与严格校验

- 单独的 `contracts` 源码区域保存公开请求/响应 JSON Schema、由其推导的 TypeScript 类型和稳定错误代码，按业务分组。游戏内容 JSON、领域模型和数据库行不直接用作 HTTP 类型；前端不导入后端领域实现、数据库、凭据或内部战术/复现包。
- 以 JSON Schema 为协议结构的单一来源，后端用于校验和响应序列化，前端复用可公开类型及必要字段校验。类型推导工具在实施时锁定并验证；不维护相互独立、容易漂移的手写前后端 DTO。领域规则仍由服务器模块验证，前端校验只帮助输入。
- JSON 写请求不做隐式类型转换、补业务默认值或删除未知字段：禁用相应校验器行为，写对象声明额外字段不允许。缺数量、类型与 schema 不符、负数量及不合法引用均明确拒绝，不能改成 1 或自动缩减；金额等约定为十进制字符串的字段仍须按其字符串语法校验。URL 查询参数本来是文本，按每个参数的明确语法解析；不是开启任意全局类型强制转换。标准 HTTP 头不按业务对象的未知字段规则一概拒绝。
- 区分未提供、显式空值、空字符串、空数组；每个端点列出语义。不支持客户端传任意对象路径来修改账号或状态，不提供通用数据库 PATCH。名称规范化只执行账号契约已经批准的规则，密码不裁剪或规范化。
- 每项输入列明长度、范围、列表项数、递归深度及正文大小限制，超限整笔拒绝。具体容量按正式内容和目标负载验证锁定，未锁定不通过实施验收；批量命令不得为绕过限制自动拆成会部分成功的多笔请求。
- 输出先构造权限允许的 DTO，再经明确响应 schema 序列化；不能把内部整对象交给前端后用界面隐藏。错误不回显密码、恢复码、令牌、SQL、堆栈或整份请求。

技术事实：Fastify 支持 JSON Schema 请求校验与响应序列化；其默认 Ajv 配置会进行类型转换、使用默认值并可移除额外字段，因此本项目必须显式覆盖这些默认行为。schema 视为可信应用代码，不接受玩家提交的 schema，数据库业务校验放在结构校验之后。[Fastify 官方说明](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/)

## 标识、数值与版本

| 字段类别 | 协议语义 |
| --- | --- |
| 账号、角色、装备、拍卖、战斗、操作身份 | 不透明字符串；客户端不推导含义、排序或归属，不用登录名/队名替代身份 |
| 请求身份 | 客户端为一次明确提交生成的高熵标识；与操作者、操作类型共同定位原操作，网络重试复用。一次 HTTP 尝试的诊断编号与此分开 |
| 对象版本 | 不透明版本值，需要保护读后修改的命令带预期版本；按一致性单元管理。钱包或体力自然变化不等于全部角色配置失效；服务器受理时固定的 Boss 等共享快照版本不自动变为客户端提交门槛 |
| 发布版本 | 覆盖当前应用和内容组合的 `releaseId`，启动上下文/响应返回当前值，新命令带读取时值；即使只有内容改变也更新 |
| 恢复代次 | `recoveryEpoch`，独立于发布版本；从旧备份恢复产生新值，旧页面请求不可通过换一个发布版本号继续使用 |
| 金钱、资产数量及其他持久大整数 | 明确范围的十进制整数字符串传输，不允许指数、小数或分组符。服务端准确解析、按字段范围校验，客户端不得先转成可能失真的浮点数再回传 |
| 有明确小范围的整数 | 等级、页大小、步骤号等可以使用 JSON 整数，但 schema 必须给出安全整数内的边界；同一字段不混用数字和字符串 |
| 体力 | 按冒险契约的整数单位返回总量、预留、可用量、恢复基准和比例；页面显示值不回写。金额、体力和战斗数值各自使用明确单位 |
| 时间 | 使用服务器 UTC 时刻和部署时区标识；截止、冷却、恢复返回绝对时刻，倒计时只是显示估计，不能决定服务器资格 |

范围在 schema、业务计算及 SQLite 转换处一致；持久整数不可超出所采用的精确存储范围，中间运算不得先溢出再检查。该传输规则不改变既有战斗取整、公式或体力单位；内部演算仍按战斗契约验证。请求摘要基于明确的规范化参数，包含会影响行为的目标、版本及业务字段；不忽略数组顺序、实例选择或条件优先级。

## 提交、查询与错误

已登录写命令携带请求身份、预期操作者内部身份、发布版本、恢复代次和该业务所需的对象版本。实际操作者来自有效会话；预期身份不匹配即拒绝，避免同一浏览器换账号后把旧页面操作作用于新账号。管理命令使用独立管理员身份和命名空间。

处理顺序为：限制/解析请求与验证会话权限 → 校验身份和恢复代次 → 查找原请求及封闭记录 → 对新操作核验发布版本、运行保护及业务资格 → 在对应短事务中再次核对请求状态并完成业务。已有操作在权限有效且参数一致时返回原状态/结果，不因当前余额、冷却或发布版本变化再执行一次。若旧协议正文已无法解析，客户端走独立的原操作查询入口；服务器不能为了返回旧结果接受任意旧写协议。

结果使用明确的判别字段，不依赖一个成功布尔值：

| 结果 | 含义与客户端动作 |
| --- | --- |
| 已完成 | 短操作事务已经提交，或原长操作已成功结算；显示实际业务结果，精炼失败/战败仍可能是已完成业务 |
| 已受理 | 长操作受理事务已提交，返回操作引用和状态查询入口；显示处理中，不提前显示成长/收益到账 |
| 待人工 | 操作与占用仍存在，展示可查询状态；不通过前端倒计时自动取消或解除占用 |
| 已取消 | 按原业务契约完成故障取消，显示已释放项及原因类别；不能理解为可以继续提交旧结果 |
| 明确未受理 | 原请求身份已有持久拒绝终态或封闭记录，不会再受理；修正条件后由用户用新身份发起新的尝试，不自动补做 |
| 结果待确认 | 客户端未取得可信响应，如超时、断线、响应无法解析；只查询原操作，不把它写成服务器终态 |

完成身份、恢复代次、请求身份和参数摘要校验后，可确定的业务拒绝（如余额不足、冷却、配置冲突或容量已满）在允许写入时保存最小拒绝终态和摘要，不产生扣费、占用或冷却。相同身份与参数重放原拒绝，改变参数仍拒绝；重试不得因条件后来改变而执行已经明确终结的请求。拒绝凭据与防重最小记录采用相同保留规则，不随完整详情到期清理。

解析失败、认证失败、限流、保护性停写或数据库不可用可能无法保存拒绝记录。能够确认在执行前拒绝的响应只说明当前 HTTP 尝试未执行，不证明同一请求身份的其他在途尝试没有受理；数据库或连接故障若无法确认提交结果，连本次尝试是否执行也不能断言。不能因此把已有的未知操作改为失败并换键重新提交，也不能为记录拒绝而越过停写保护。客户端继续核对原操作；原参数仍在内存且当前允许提交时，可由玩家主动用同一身份重试，此次可能完成原来从未受理的操作。HTTP 状态码本身不是原操作的持久终态。

操作查询按当前有权操作者及原操作身份查找，不能提供任意账号 ID 来越权查询。暂时找不到只表示当前没有可返回的记录，不证明旧请求不会稍后受理。短操作结果响应丢失、长操作已受理及正在恢复都通过同一查询语义处理；已保存的终态不能被后来的旧响应降级为处理中。

Q6 的“结束本次核对”是用户主动发起的独立具名命令，仅携带原查询引用和当前有效身份/版本上下文，不需要原正文。服务器在同一短事务内检查当前账号、恢复代次和原请求身份：已有操作或拒绝/封闭记录则返回原状态；尚无记录则保存永久阻止该身份首次受理的最小封闭记录。封闭记录即使没有原参数摘要，也拒绝该身份携带任何参数执行；普通请求必须在受理/业务提交事务内复核，不能靠事务外“未找到”检查绕过封闭。封闭与原操作受理只有一个能先成功，已受理不受封闭影响。

封闭本身可重复查询和手动重试，超时仍为待确认；只有取得持久的未受理终态，客户端才允许将这次未知操作结束并按当前状态另行填写提交。它遵守会话、来源、当前发布版本和所有停写保护；维护期间只查询，更新后先刷新，原账号停用时不能绕过限制。不得自动封闭、取消战斗或撤拍。封闭凭据沿用最小防重记录的保留边界；灾难恢复代次隔离先于任何旧引用处理。

完整结果超过保留期限时，仍有最小凭据的操作可返回终态与“详情不可查询”，不再次执行。历史收据中的余额/版本是当时结果，不覆盖当前钱包或角色状态；完成后另外读取当前视图。删除回执 7 天、战报状态回执 1 年及完整流水等期限沿用运行契约，不另设无限详情缓存。

HTTP 状态与结构化错误共同表达结果：正常查询/完成使用 200，长操作受理使用 202；400 为结构不合法，401 为身份验证需要，403 为已认证但操作不允许，404 为不可访问或不存在，409 为版本/占用/请求参数冲突，422 为合法结构下业务条件不满足，429 为限流，503 为维护/保护或暂不可用。稳定 `code` 区分具体业务原因，必要时附允许公开的字段错误、当前版本、冷却截止或稍后查询提示。业务拒绝与网络代理生成的 5xx 不混淆；无可信操作结果的 5xx 仍进入结果待确认。

响应元信息至少可关联服务器诊断编号、服务器时刻、发布版本和恢复代次；网关错误可能不满足 JSON 格式，客户端必须有未知结果处理。恢复代次变化优先于发布更新、对象冲突和原操作结果处理，不自动升级旧线索为新代次。

## 认证、隐私与恢复

使用已确认的 HTTPS、服务端会话及 HttpOnly/Secure Cookie；玩家和管理员使用不同会话作用域。明确采用 SameSite=Lax，并为状态修改请求校验预期 Origin 和与会话绑定的 CSRF 凭据；未登录注册/登录/恢复也校验来源和允许的请求格式，不以同源部署为由免除防护。具体 Cookie 名和部署代理匹配在实施核验，日志不得记录敏感头或正文。

401 先停止原身份私有查询和新操作，清除在屏幕上展示的私有服务端数据；普通过期可保留原身份的内存草稿及只用于查询的线索。重新登录后先核对内部身份和恢复代次，再读取最新状态和恢复原只读位置。名字相同而内部身份不同视为换账号；旧查询迟到响应不得填入新账号页面。

注册、恢复码重置、改密和重新签发等沿用账号契约的特殊恢复方式：不把密码或恢复码放入普通结果缓存，不重放恢复码明文，必要时以新密码登录后重新签发。自助删除仅使用既有删除回执查询规则，不套用需仍有效账号会话的普通操作查询。管理员近期验证失败不能通过玩家重新登录替代；已受理固定范围后台任务继续执行，后续查询仍须当前权限。

私有模拟战报先鉴权，未登录请求可以保存非敏感的原页面位置并引导登录。已登录但无权与不存在使用同类不可查询响应，只有有权访问原记录的人才能区分过期或已清理；不泄露他人私有操作 ID、结果或忙碌详情。

标签页会话存储按账号与恢复代次隔离，只保存 Q5 的查询线索，其中操作引用包含定位所需的类型/请求标识。查询得到终态后清除不再需要的待确认线索；私有服务端数据不落长期浏览器缓存。存储不可用时保留内存线索并说明刷新后只能从游戏记录核对。刷新已失去请求正文时不能重发原业务，只能查询或由玩家主动执行 Q6 的结束核对；不得从查询标识猜参数重建购买、竞价或出战请求。

## 刷新与客户端读取状态

每个查询同一时刻最多一笔在途请求，不叠加定时器、网络恢复和页面切换造成的重复轮询。账号的正式/模拟状态集中查询，当前展示的拍卖/Boss/排行按需查询，不在每个组件重复发全站请求。隐藏页面暂停自动查询，离线暂停发送，恢复可见/网络后重新读取；失败采用有界退避，429/503 尊重服务器提示，保留可重试入口和最后成功更新时间。

在每次登录、账号切换、恢复代次改变和页面查询条件改变时隔离旧请求上下文；较旧响应不能覆盖当前身份/页面或更新的结果。命令完成时使受影响的读取失效并重新获取服务器当前状态；执行中的旧查询不能把该动作前的状态覆盖回来。前端可以显示输入预览或待处理标记，不把乐观更新当成已提交资产或配置。

自动刷新更新已保存的服务器视图，不覆盖战术草稿或正在填写的金额、数量。拍卖价格、角色版本等依赖变化时标记需核对，不能替用户提高报价或换最新版本号继续提交旧编辑。共享玩法的忙碌、账号冷却和服务器处理容量分开显示，不混成一个等待倒计时。

自动请求明确标记为自动读取，不续会话闲置期；服务器按允许的请求种类与自身时间处理有效用户活动，客户端时间不可信，活动标记不充当身份或操作授权。界面倒计时以最近服务器时刻估计，前台定时校正；显示到零不代表写操作一定会被受理。

检测到 Q4 更新后，不强制刷新、不自动保存草稿；提供草稿文本复制供玩家自行保留，复制不赋予导入/自动执行能力。刷新后加载匹配发布版本的资源与定义。只允许查询原操作，不用当前 `releaseId` 改写已排队或尚未确认的旧写请求；因版本不匹配明确未受理后，玩家按新版重新核对并发起新尝试。

## 列表、战报与缓存

- 账号信息、钱包、角色配置、操作状态及模拟战报使用不允许共享缓存的响应；账号切换、退出、恢复代次变化清理相应页面数据。任何缓存命中都不能绕过当前授权、到期或管理清理。
- 公共公告、留言、拍卖、排行和战报的可变内容首期不依赖 CDN/代理长期缓存，查询返回已提交状态及更新时间。已撤下公告、隐藏留言、清理战报不能由另一读取入口或旧服务端缓存继续提供；这不承诺收回别人已经下载的内容。
- 不变静态素材按版本地址缓存，按运行契约保留历史依赖。公开内容资料返回当前允许展示的字段及定义版本，不含未开放资料、完整战术或秘密配置。
- 历史战报/交易/流水按稳定顺序和游标读取；游标绑定筛选、访问范围及排序，不作为权限凭据。静态步骤目录可分批，步骤通过明确编号定位，加载前后相邻步可有界预取；翻页不下载整份内部复现材料。
- 可变拍卖/竞技列表明确读取时版本，分页游标同时绑定该版本、筛选、访问范围及排序。后续页只允许在同一版本下读取；若列表已变化，返回明确的分页版本冲突，客户端从第一页重新读取，不追加旧页，不要求首期保存历史列表快照。具体页大小在实施约束表锁定，并验证更新、删除、到期和同刻多条记录下的行为。
- 战报目录、单步、关联事件与双方状态以同一场固定记录为准；一次步骤读取需返回相互对应的结果。加载中不能把新标题配旧阵型，失败保留原步骤并说明目标步骤未加载；返回目录恢复来源条目，记录过期/清理时显示相应状态。

## 代表性命令和查询

下表确定操作语义与读取责任；路径命名、具体 JSON 字段及生成文档在实施时按共享 schema 落地，不要求每行独立成软件包。

| 场景 | 提交和响应 | 随后读取/冲突 |
| --- | --- | --- |
| 启动/登录 | 读取公共运行状态；登录建立原规则会话 | 核对内部身份、当前发布/恢复代次，读取账号概要与在途操作 |
| 保存/交换战术 | 整体方案、角色预期版本；保存或交换成功后返回变更凭据 | 刷新已保存方案，保留尚未提交草稿；版本/占用冲突不给成功提示 |
| 保存并单人测试 | 一个协调命令，同时检查保存与模拟受理条件；一起提交保存和固定测试输入 | 保存成功与模拟处理中分开呈现，演算故障不撤销保存 |
| 成长/转职/装备 | 具体角色、技能/定义/装备实例和依赖版本 | 单次事务结果；读取相关角色、装备位置及资产，不把同名装备合并身份 |
| 购买/出售/制作/精炼/打工 | 明确目标、数量/实例及所需版本；服务端计算价格和随机结果 | 完成结果区分游戏失败与拒绝，刷新最新资产；连续精炼实际批次一次提交 |
| 普通冒险/团队模拟 | 地图及成员、相关配置版本、记忆选择等显式参数 | 返回正式或模拟操作引用；只查询原操作，完成后链接权限允许的战报 |
| 结束本次核对 | 原账号范围内的操作类型/请求标识及恢复代次；事务内检查并仅封闭尚未受理身份 | 已受理返回原状态，封闭成功返回持久未受理终态；超时只查询或手动重试封闭，不重建原业务 |
| Boss 挑战 | 明确实例、所选角色及配置版本、记忆选项；受理时由服务器固定当前有效轮次和共享状态版本 | 不因页面 HP 已变化而额外拒绝；忙碌/死亡仍按原规则判断。受理后查询和恢复固定原挑战，不换轮次或重新抽样 |
| 竞技设队/挑战 | 设队提交明确名单及所需版本；挑战不指定对手，由服务端按受理时榜单和原抽选规则固定对手与双方快照 | 全榜忙碌与个人限制分开；异常不换对手重抽。空榜有效挑战直接返回入榜完成，不虚构战斗、战报或冷却 |
| 上架/竞价 | 确定拍品/数量和报价、拍卖版本；金额不能因页面刷新自动提高 | 冲突返回有权读取的当前价格/状态；到期禁止投，待结算与已到账分开 |
| 留言/公告 | 合法文本、对象、请求身份；管理修改附原因及版本 | 发言冷却和窗口按已有规则；读取公开/私有范围，不用成功弹窗掩盖拒绝 |
| 管理修正/清理 | 具体目标、预期版本、原因及所需近期验证；长任务固定目标范围 | 短操作提交时再鉴权；长任务返回引用、进度和结果，不扩大授权范围 |

查询投影按页面用途组合，区分公共资料、账号私有状态和管理员诊断。客户端不依赖数据库列名，不通过大而全的账号对象更新任意模块。

## 必须通过的实施验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| 同次购买响应丢失、客户端手动重试，期间余额变化 | 查询/重试返回原结果，只扣发一次；旧收据不覆盖当前钱包 |
| 原请求仍在途，查询暂时无记录 | 显示待确认，不自动另开新请求，不宣称一定失败 |
| 原请求未到达、刷新丢失正文，封闭与迟到受理竞争 | 只有受理或封闭之一先成功；已受理不取消，已封闭永久拒绝迟到首次执行。封闭响应丢失可查询终态 |
| 业务拒绝/认证失败/限流/停写响应与旧请求交错 | 持久拒绝按原终态重放；非持久拒绝不把其他尝试的未知状态误判为失败，不越过保护写库 |
| 同请求身份换参数、跨账号/管理身份使用 | 拒绝参数或上下文不匹配，不能读取或改变其他身份的业务 |
| 刷新、普通过期登录、切换同名不同身份账号 | 仅同内部身份恢复查询/内存草稿；无自动写入、跨账号数据或凭据泄露 |
| 发布更新与已受理业务并存 | 新的旧版本写入拒绝，已受理操作可查原结果；页面不强制刷新吞掉草稿 |
| 灾难恢复代次变化，旧页面/请求迟到 | 清除旧线索与上下文，不自动换代次重发或恢复旧管理员权限 |
| 后台/离线/网络抖动、轮询与命令响应乱序 | 无叠加轮询，旧结果不覆盖新视图，自动读取不续会话；间隔和退避经过负载验证 |
| 非法数量、未知字段、丢失字段、大整数与小数体力 | 不隐式修正输入、不丢精度，HTTP/业务/存储范围一致，整笔拒绝非法批次 |
| 正式/模拟深链、ID 猜测、过期和管理清理 | 授权范围正确，无私有存在性泄露，缓存不能绕过权限或详情清理 |
| 长战报跳步、相邻预取、清理发生在读取期间 | 标题/事件/阵型一致，失败保留原步，返回目录恢复来源，不演算/抽样 |
| 拍卖或榜单翻页期间发生竞价、删除或排名变化 | 版本一致才接续分页；不一致重新读取，不混排、不把旧游标当访问权限 |
| 多人竞价、Boss 忙碌/换轮、竞技排名变化 | 按各玩法规定的版本与受理资格裁决，不自动加价或换对手；Boss 受理固定当前有效轮次，后续恢复不能换轮 |
| 注册/恢复/改密/删号的响应丢失 | 各自按账号契约恢复；不重放恢复码或把普通私有查询套在已删除账号上 |

当前只有规划及官方文档核对，尚未生成路由、schema、客户端代码或执行上述运行验收。[完整覆盖验收](https://github.com/odradekk/hof_redux/issues/18)负责浏览器矩阵、真实手机及接口负载门槛，[实施切片](https://github.com/odradekk/hof_redux/issues/19)据本契约拆分交付。
