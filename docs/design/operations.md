# 运营管理工具与修正操作契约

状态：已确认。用户已逐项确认 Q1–Q16，并在 Q17 确认完整契约。对应[确定完整运营管理工具与修正操作契约](https://github.com/odradekk/hof_redux/issues/15)。本文件是规划规格，不表示管理工具已经实现。

前置：[账号与会话](accounts.md)、[状态与事务](state-transactions.md)、[内容发布](content-release.md)、[交易](trading.md)、[竞技场](arena.md)、[世界 Boss](world-boss.md)、[展示与公共信息](public-information.md)。旧能力清单见[后台与公共证据](../legacy/operations-and-public.md)。

## 已确认的行为

- Q1：管理员可针对单个账号，按明确数量补发或扣回金钱、体力、材料和装备，用于补偿与纠错。执行前展示对象、变化与原因；扣回不能产生负余额、动用已预留体力或直接拿走拍卖托管、战斗占用的装备。数量不足整笔拒绝，不自动追缴给其他玩家，不改写原交易或战报；装备按具体实例处理。角色成长与装备属性修正见 Q3/Q4。
- Q2：管理操作记录只允许追加和查询，不允许管理员编辑或逐条删除。记录操作者、对象、原因、时间、实际变更与结果；纠错追加关联记录，成功管理变更与记录在同一事务提交，不记录密码或恢复码。保存期限与到期清理见 Q12。这是管理功能的约束，不声称服务器管理者在技术上无法改动数据库。
- Q3：提供角色成长修正，允许纠正职业、等级、剩余经验、基础属性、未分配属性点与技能点、已学技能。明确填写需要修改的字段，预览前后差异并说明依据；整个目标状态须通过一致性校验。若导致装备不合法或战术引用失效，必须同时明确处理方案，否则拒绝，不静默卸装或删技能。战斗占用中的角色不能修改；修正不重新发放过去的升级收益，不改历史战报。
- Q4：允许修正指定装备实例的精炼等级与已记录附加效果，使用确定目标值，校验当前定义允许的精炼范围、效果类型、来源和顺序；不提供随机重抽，不修改装备定义或所属账号。拍卖托管和战斗占用期间拒绝修正。补发装备也采用明确、合法的实例属性并创建新身份；操作均预览差异、填写原因并留记录。
- Q5：管理员可因名称违规或数据纠错，免费修改队伍名和角色名；填写明确新名称与原因，遵循既定长度、字符和队名唯一规则，不消耗玩家金钱或改名道具。旧队名释放，历史战报和留言保留当时名称。角色出战占用结束后才可改名；玩家自行改名仍按原约定收费。
- Q6：除移除无效榜内账号外，允许依据可核查记录修复竞技榜单顺序与累计战绩。提交明确目标顺序或统计修正，预览全部受影响账号及差异，附原因与依据；整个竞技场无进行中挑战时才可执行，提交时重新校验榜单版本。修复不伪造对局胜负，不改历史战报，不刷新挑战冷却，不提供无依据的一键清榜或赛季重置。
- Q7：竞技名单损坏时，有可靠依据且原成员仍合法存在，才可恢复原成员与顺序，并保留原登记时间；不允许管理员任意替玩家换队。无可靠依据或原成员已不存在，则移出榜单、清理无效名单，由玩家重新登记，新登记开始新的 48 小时限制。处理须等竞技场空闲，不重置累计战绩或主动挑战冷却。
- Q8：世界 Boss 常规管理限于状态诊断、按原规则检查复活、恢复原挑战，以及确认无法完成后的故障取消，不设随意改血、强制击杀或提前复活按钮。真正的数据损坏通过单独审阅的事故修复方案处理，明确目标实例、轮次、依据和前后状态，无进行中挑战时执行；不能重复发放奖励或改写历史战报。
- Q9：日常拍卖开关仅暂停新上架，可按全服或物品定义设置，记录原因与操作者；既有拍卖继续竞价、计时和到期结算，不另设日常禁止竞价开关。异常拍卖可按已有取消退款契约处理。全站维护仍遵守既定写入暂停与现实时间计时规则。
- Q10：保留有限 IP 核查：只保存账号最近一次成功登录 IP，管理员可查询同 IP 账号，仅作为排查线索，不自动处罚或禁止交易。超过 30 天无新登录即清除，删号时也清除，不建立登录 IP 历史轨迹。查询须填写核查原因并留记录，IP 不向玩家公开。
- Q11：旧怪物战术生成器由后台完整只读核对与开发侧 JSON 编辑、校验、发布流程替代，首期不提供可视化编排界面。后台展示怪物战术的顺序及参数；修改在仓库中完成，不直接改变运行中定义。
- Q12：管理操作记录自产生起默认保留 1 年；公告旧版本自被替换或撤下起默认保留 1 年，当前公开版本持续保留；留言原文自发布起至少保留 90 天，仍处于玩家 50／150 条窗口内则继续保留。过期留言的管理记录只保留对象、动作和原因，不另存原文副本。期限可作部署配置，到期自动清理，管理员不能逐条删除；资产流水及结算凭据期限仍归运行专题。
- Q13：资产统计按同一时点覆盖钱包余额、拍卖暂存竞价款、背包、穿戴装备和拍卖托管物，分项及汇总展示，每件装备只计一次；支持按物品定义、精炼等级和附加效果筛选。人均分母为全部已创建且未删除的玩家账号，包含停用和未建队账号，空服显示 0。继续提供角色数量、等级、属性与职业分布。
- Q14：后台只开放维护控制、全服/按物品暂停新拍卖上架、外部论坛链接控制；其他配置通过部署或内容发布修改，不做通用在线编辑器。展示实际生效值、来源与版本，隐藏凭据；变更遵循既定生效时点与数据保护约束。
- Q15：修改玩家或共享玩法状态、运行控制项、批量战报清理及 IP 核查属于敏感管理操作，要求最近 5 分钟内成功验证密码；包括停用/恢复/删除账号、资产/成长/装备/名称修正、竞技修复、拍卖取消、故障取消等。公告发布/修订/撤下、留言隐藏/恢复只要求有效管理会话、明确对象与原因并留记录；普通只读查询不额外要求近期密码验证。
- Q16：战报清理任务通过有效管理员身份、近期密码验证、固定范围预览与明确确认并成功受理后，后台各批次和故障续跑继续执行，即便原管理员退出、会话到期或身份撤销；只能处理原固定目标，记录原管理员及批次结果。短操作仍在提交时检查会话与近期验证，新建或扩大任务必须重新授权。


## 沿用的约束

- 管理员使用独立具名身份，首期统一权限、仅密码验证。会话闲置 15 分钟、最长 8 小时；敏感短操作最终提交时、清理任务受理时要求最近 5 分钟内成功验证密码。敏感操作范围见 Q15。
- 各管理入口调用所属模块的业务操作，遵循事务、版本、业务占用与幂等约束。管理页面不提供原始数据库或文件编辑；失败不能留下部分变更，重试不能重复补发或扣回。
- 管理修正追加业务流水，不覆盖旧流水；管理记录说明管理员的操作，业务流水说明资产和成长实际如何变化。关联原业务不等于重新执行原结算。
- 账号停用、删除，拍卖取消退款，竞技异常处理，留言隐藏与恢复，公告发布、修订与撤下，四类战报清理，均沿用相应前置契约；不得通过后台绕过其限制。
- 游戏定义经内容发布流程更新，后台不绕过发布流程在线改定义。数据库灾难恢复与普通业务修正分开，运行专题另定恢复方案。

## 操作与修正边界

### 共同执行规则

管理查询与写入的每个接口都验证管理员身份，不以菜单隐藏代替鉴权。对象使用稳定账号、角色、装备、拍卖或操作身份；显示名称只帮助核对，不能使同名新账号承接旧修正。管理员不能读取玩家密码、恢复码或会话令牌，登录名继续遵守注册后不可修改的账号契约。

每次写入提交具体操作、目标、预期版本、规范化参数、请求身份与必填原因。修正和破坏性操作先展示实际影响，再明确确认；不能上传整份账号、角色或数据库内容代替命令。短操作最终提交时重新校验身份、Q15 所需的近期密码验证、目标状态、占用及相关版本，更新所属模块状态、业务流水、管理记录与操作结果。任何一步失败全笔回滚；已成功的同请求重试返回原结果，变更参数须作为新操作重新确认。

Q16 的清理任务在受理事务提交时完成上述授权检查，并保存不可扩大范围的任务授权与原管理员身份。后续批次验证持久任务身份、范围、执行代次与目标条件，由系统任务执行，不借用原浏览器会话；退出、会话到期或撤销管理员不取消该授权。新建、改参数或扩大任务都须重新预览和授权。每批清理效果、进度与记录一起提交，故障续跑只处理未完成目标。维护发布的写入暂停仍优先适用；维护期间暂停处理不等于撤销任务，恢复后继续原任务。

预览不是占用或执行许可。预览后相关状态变化导致结果不同，必须重新预览确认，不自动套用新版本重发。多对象修正明确列出全部目标与关联影响；不能以模糊的“所有异常记录”作为持续扩大范围的授权。诊断与管理原因是纯文本，不接受执行脚本。

### 资产、成长与装备

- Q1 以明确增减量和实例清单表达；扣回只能动用当前可用资产，受体力上限、资源预留、装备位置与战斗占用约束，不能部分扣回、形成欠款或沿交易链自动追缴。体力先按原规则计算恢复，再执行修正，不重置恢复时间来隐性增减。补发或扣回越过合法范围时整笔拒绝，不静默截断数量。
- 装备补发创建新身份并进入目标账号背包，记录修正来源及明确属性。扣回或修正某件已穿戴装备须检查其当前角色和槽位；扣回时明确预览卸下并收回原实例的影响，同一事务清理槽位关联，不能留下角色仍引用已收回物品的状态。拍卖托管和战斗占用仍阻止操作。
- Q3 使用当前完整成长状态加明确变更字段形成目标，再统一校验职业引用、等级与经验关系、基础属性及点数范围、技能引用、装备许可和有效战术。不能仅改等级却隐含再次发点，也不能用当前职业的学习列表误删转职前合法学得的技能。历史已分配成长不会因当前定义变化被自动反推重算。合法性检查不等于重新执行一次招募、转职或技能学习，也不自动证明管理员给出的目标曾在历史中真实存在；管理员须记录具体依据，缺少证据的历史不能由工具编造。
- 修正涉及装备迁移或战术变更时，预览必须逐项列明，并按角色与物品模块规则一起提交。正常规则允许保存的超出有效行数部分仍按既定战术规则隐藏，不以“修正”名义静默丢弃；没有明确合法处理方案就拒绝。
- Q4 只改变原装备实例的精炼和有序附加效果状态，不改定义、身份或所有者；校验效果适用分类及组合，不能借逐个效果都存在而组合出非法装备。修正已穿戴装备还须基于完整目标实例重新校验角色职业许可、占槽及总承载，仍合法才原位提交；若须卸回背包，应预览并明确确认该处理，与实例修正同事务完成，否则拒绝，不能静默卸装。不随机生成目标，也不重新收取正常制作或精炼费用。
- 日常工具不提供账号或角色归属转移、整号存档导入、回填旧战报、直接写普通角色战斗临时 HP/SP 等操作。超出已定义修正范围的数据损坏须形成单独的事故修复方案，不能退回通用数据库编辑器。

### 竞技与 Boss

Q6 修复后的榜单仍是稳定账号组成的有序列表，成员不重复且具备合法竞技名单，按 1／2／3／3…容量分档；无空档，只有末档可不满。累计统计非负，总场次等于胜、负、平之和；成功守冠次数保持原语义。修正目标与依据明确，不能把未知历史补造为对局；原战报和结算凭据不变。

名单按 Q7 修复或移榜，不能仅从坏名单中去掉一个人便把缩小的队伍继续留榜。移榜按原顺序补位并清理该账号竞技名单，名单重建不能清除仍有效的主动冷却。所有竞技修复在无进行中竞技挑战时原子提交；修改单方统计也不得与对局的双方战绩结算竞争。

Boss 普通诊断区分实例、轮次、已提交剩余 HP/SP、当前上限求值条件及挑战占用。人数减少造成剩余 HP 高于新上限是已批准状态，不能自动当作损坏并截断。按规则检查复活仍由 Boss 模块判断严格时间条件；Q8 的事故修复不属于日常改血或提前复活能力。

### 故障与一致性诊断

| 对象 | 管理工具与边界 |
| --- | --- |
| 普通冒险、竞技、Boss 及保存中的模拟操作 | 查询受理输入版本、处理阶段、执行代次和错误；按原输入继续处理。正式战斗沿用原随机输入，不能新开一次代替恢复 |
| 确认无法恢复的战斗 | 确认未有成功结算并隔离旧执行者，按原操作版本原子取消、释放其占用和预留；迟到结果不能提交。取消无收益、费用或本次冷却，不提供裸解锁或强制标成功 |
| 异常拍卖 | 查看标的、暂存款、到期与终态；重试同一到期结算或按既定规则取消未结拍卖。已结束拍卖不能重开，不能改赢家、金额或截止时间 |
| 战报清理任务 | 查询固定范围、已处理数量和错误，续跑原清理任务；不扩大目标、不恢复已删详情、不删除结算或仍被业务使用的数据 |
| 一致性检查 | 查询悬空引用、名称唯一性、装备归属与位置、负资产、预留与占用关联、拍卖资金与标的、竞技结构和 Boss 轮次异常；只出具诊断，不在查询时自动修改状态 |

短暂数据库忙、执行租期届满、玩家断线或管理员不愿等待都不构成故障取消依据。等待的原业务仍有效；如果现有命令无法安全修复，保留证据并制定明确方案。诊断的正常范围包括账号未建队、零角色、停用、空榜等合法状态，不能把它们自动清理掉。

## 查询、统计与运行控制

后台提供账号检索、详情和与其关联的角色、当前资产、业务流水、未结操作、拍卖及竞技状态查询。查询受管理权限与各类留存限制约束；账号删除后只展示允许保留的历史身份和记录。普通账号详情不附带 IP；任何返回 IP 或同 IP 关联结果的入口都遵守 Q10/Q15 的核查原因、近期验证和记录要求。管理员可查私有模拟战报，但仍不能绕过详情已过期或已清理的状态。

Q13 的资金总额为现存玩家钱包余额与拍卖暂存竞价款之和，分别展示；最高出价已从钱包支出，不能重复计算，已收取消耗费用不算玩家现存资金。物品统计按真实位置归类，拍卖数量只计在托管项；装备每个实例计一件，材料按数量计数。各项统计来自同一一致读快照并标明生成时间，不跨不同状态分别求和，也不长时间持有写事务。账号人均按 Q13 分母，角色平均等级/属性按现存角色数计算，空集合为 0。筛选附加效果不将一件带多个效果的装备计成多件。

内容查询覆盖已发布版本的物品、效果、职业、技能、条件、怪物、地图、掉落和配方，以及版本、校验和迁移报告。完整可执行但未开放、已下架但仍可用、仅保留来源的档案均明确区分，档案不伪装成可运行内容；后台的完整怪物战术信息不进入公共图鉴接口。

运行控制的生效状态与操作者原因持久保存，重启不悄悄解除暂停。全服暂停与按物品暂停任一命中即拒绝新上架，取消一个条件不抹除另一个；暂停不隐藏既有拍卖，也不挡退款和到期交付。已受理操作照原规则完成。外部论坛链接按既定 HTTP(S) 与统一开关规则校验，关闭后所有玩家入口消失。

维护控制进入既定的暂停新写入、排空、切换流程；不得以普通开关操作跳过排空与发布校验。维护期间的控制权限、故障退出和部署切换的具体实现由运行专题确定。Q14 的只读配置页不显示密钥、密码、数据库连接秘密或会话凭据。

## IP 核查与内部记录生命周期

Q10 只使用未过期的最近成功登录地址；失败登录、浏览活动和其他游戏操作不刷新该字段的时间。地址与成功登录时刻一起更新，删号时清除；停用本身不延长保留。查询先验证管理权限与最近 5 分钟密码验证并记录核查原因，不用 IP 作为登录身份、处罚结论或交易资格。同 IP 查询只表示当时保存值相同，不能断言同一自然人。

核查审计记录目标账号身份、查询类型、时刻和原因，不把原始 IP 另复制到长期管理记录、操作参数副本或查询导出中形成第二份历史。应归一化合法 IPv4/IPv6 地址；可信代理及网络来源识别交运行专题落实，不能直接信任客户端任意提供的转发头。基础设施请求日志另由运行专题确定范围与期限，不以此管理查询功能默认授予完整访问日志。灾难恢复也按当前时刻和原登录时刻判断到期，旧备份中的已过期地址不能重新变为可查；恢复隔离与清理由运行专题落实。

Q12 的留言到期清理同时满足“已满内部保存期”和“已退出原板块数量窗口”；隐藏不改变窗口归属，恢复不重置发表时间或延长内部保留。超过窗口但尚未到期的原文仅供管理核查，不能恢复进玩家列表。管理记录不复制留言正文，原因也不得用作存放完整原文的替代字段。

公告只有被替换或撤下的版本开始计算内部历史期限；公开当前版本即使超过一年仍保留。审计可用版本身份、动作和摘要关联正文，不用另一份永久正文副本绕过 Q12。记录过期不使仍存续的业务、唯一结算身份或最小幂等凭据失效；未完成任务所需记录仍须保留至其依赖解除。

到期清理可批量执行，但须留下清理类别、范围、数量和结果，不在同批删除自己的清理记录。物理清理延迟不使过期 IP 或历史正文继续可查。[运行方案](runtime.md) 统一记录各类期限及默认配置变更的生效方式；Q21/Q22/Q25/Q26 已确认流水、内部复现、查询回执及运行日志的独立保留规则。管理提前清理可见战报不提前删除内部复现材料，所有清理均不得解除业务去重或在途依赖。

## 必须覆盖的验收场景

| 场景 | 预期结果 |
| --- | --- |
| 普通玩家、未登录者、过期或已撤销管理员直调后台接口 | 所有管理页面及 API 拒绝访问；不能靠工具页直达绕过认证 |
| 敏感操作预览后超过 5 分钟才提交；公告日常修订 | 前者要求重新验证，后者按有效会话及版本正常处理；普通浏览不刷新密码验证时间 |
| 管理修正响应丢失、同请求重发或更换参数 | 原结果可查，补发/扣回不重复；原请求换参数拒绝 |
| 扣回超出现有可用余额、预留体力、托管或出战装备 | 全笔拒绝，预留与原交易不受影响，不自动截断数量或追缴他人 |
| 补发装备；收回穿戴装备；修正装备后并发出售 | 新实例身份唯一、槽位关联一致；版本与位置冲突拒绝，修正后穿戴仍须合法；卸回背包须明确确认，不产生重复持有或遗留引用 |
| 降级或改职业造成经验、点数、装备、战术不一致 | 整体校验；无明确合法目标方案拒绝，不隐性补点、删技能或改历史 |
| 原有角色已学前职业技能；属性修正减少有效战术行 | 不误删合法继承技能，超出有效行的保存与隐藏仍遵守已确认战术规则 |
| 管理改名后旧名被新账号使用 | 当前身份及名称索引正确，历史名称不改写、不归新账号，不收取玩家费用 |
| 修复榜单/统计时另有竞技挑战；无效名单原成员不存在 | 前者拒绝；后者移榜并清理名单，保留统计与主动冷却，重新登记开启新 48 小时限制 |
| Boss 剩余 HP 高于新上限；请求强制复活 | 前者按合法状态展示；后者无日常工具入口，规则检查不跳过复活条件 |
| 旧执行者迟到；短暂忙碌；无法恢复时取消 | 旧执行代次不能提交；短暂忙碌不裸解锁；确认取消后无成本、收益或本次冷却，原占用原子释放 |
| 到期结算与管理员取消同一拍卖竞争 | 仅一个终态生效，退物、竞价款与上架费不重复，已成交不能再取消 |
| 全服暂停和按物品暂停叠加；重启；已有出价和截止时间 | 按任一暂停拒绝新上架，重启保留开关；既有竞价、到期交付不被日常暂停阻断 |
| 资产统计遇到穿戴、托管、同装备多个效果或空服 | 位置分项与汇总一致，实例不重复，竞价款不重复计入钱包，空集合不除零 |
| 登录地址变更、满 30 天、删号、旧名复用 | 最近值更新且有时间依据；过期或删除不再可查，不通过审计副本恢复历史地址 |
| 留言退出窗口未满 90 天；满 90 天但仍在窗口；隐藏后恢复 | 前者仅管理可查，后者继续保留；恢复不回到窗口或重置时间，隐藏不把更老留言补入窗口 |
| 公告当前版超过一年；旧版过期；管理记录清理 | 当前公开版仍在，过期旧文不再可查；到期清理不删业务凭据或重置幂等身份 |
| 公告/留言管理并发；私有报告过期；批量清理后重试 | 按版本拒绝覆盖，权限与过期状态一致；原清理范围固定，重试不扩大或复原已清详情 |
| 批量清理受理后原管理员退出、到期或撤销；维护；重启 | 原固定授权继续有效，按任务身份及代次续跑；维护写入门暂停批次，恢复后不扩大范围；新任务重新授权 |
| 内容查询未开放档案、怪物完整战术与配置秘密 | 管理只读且明确状态；公共接口不泄露完整战术，后台不泄露凭据或在线改定义 |

以上是实施验收要求，不表示运行测试已经通过。

## 补核的源码事实

- `old_hof/admin/admin.php:128–154` 接受文件内容并整体覆写，不能证明旧版存在独立的资产补偿、成长修复等命令；上述具体操作来自本专题的用户决定。
- 旧物品统计在 `admin/admin.php:248–262` 只读取背包；穿戴操作从背包扣除装备（`class/class.main.php:549–575`），上架亦从背包移出拍品（`:2682–2689`），因此旧统计不覆盖这两类资产位置。
- IP 核查在 `admin/admin.php:267–286` 使用账号单一 IP 字段，成功登录设置来自 `class/class.main.php:3260–3261` 的远端地址。源码不能证明实际部署的代理拓扑，也不能证明该地址一定是真实客户端地址。
- `admin/set_action2.php:78–98` 输出战术 PHP 数组文本；它不是运行期内容保存或发布入口。后台配置表 `admin/admin.php:499–526` 也仅展示值。

以上路径均位于 `old_hof/`，只核对所需源码；未执行 PHP，未读取玩家存档、实际日志或凭据。
