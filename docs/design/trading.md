# 商店、拍卖与到期结算

状态：已确认。Q1–Q8 及 Q9 完整契约均经用户确认。对应[确定商店、拍卖与到期结算规则](https://github.com/odradekk/hof_redux/issues/10)。这是规划，不表示交易实现、并发测试或运行验证已经完成。

前置：[状态与事务契约](state-transactions.md)、[内容模型](content-model.md)、[内容发布](content-release.md)、[保真基准](../legacy/fidelity-decisions.md)。保留旧正式交易能力，不增加玩家自由赠送、买断、代理竞价或玩家主动撤拍。

## 已确认的裁决

- Q1：取消买家与卖家上架时 IP 相同就拒绝竞价的限制；仍禁止卖家本人和当前最高出价者竞价。移动端正常开放，操作留有核查记录，首期不增加复杂反作弊系统。
- Q2：存在未结卖方拍卖，或仍是未结拍卖最高出价者时，禁止自助删号并列出原因；被超价并完成退款后解除该笔买方义务，已结束历史不阻塞删除。
- Q3：取得写入机会后，在事务内取服务端时刻检查截止边界；`now >= endsAt` 不接受新报价，即使请求更早到达或到期任务尚未运行。后台自动结算，不依赖访问拍卖页或账号在线。
- Q4：购买、出售、上架数量为明确的正整数；不能把非法值改为 1，也不能把不足数量缩减后成交。批量任一项失败则全部失败，合法零价格定义保留。
- Q5：上架成功后 30 秒限制统一按账号计算；失败和原请求重试不重置。保留全服最多 100 笔未结拍卖，不增加每账号并行上架数量上限。
- Q6：更新会改变在售拍品属性或使用条件时，默认阻止发布，先暂停相关物品新上架并等待受影响拍卖结清；紧急更新须有明确的取消退款方案。无关更新可继续，已有拍卖沿用上架时费用、加价和延期规则。
- Q7：管理员可取消尚未结算的拍卖，原子退回全部拍品、最高出价者的全部出价和卖家已付上架费；有权限校验、必填原因和流水。已成交、已流拍或已取消的拍卖不能再次退款。
- Q8：维护和停机不暂停拍卖现实时间、不自动延期；恢复后先按原截止规则处理到期拍卖，不能补投。计划维护提前告知，特殊处理通过有记录的取消退款完成。

## 商店与打工

| 操作 | 保留的旧规则 | 新版提交边界 |
| --- | --- | --- |
| 购买 | `ShopList` 的 39 个正式基础物品；无库存限制；单价为定义 `buy`，总价为单价乘数量 | 验证当前商品与客户端确认的价格/内容版本、正整数数量、金额及可用余额；扣钱和全部入库同一事务 |
| 出售 | 所有背包物品；优先使用显式 `sell`（包括 0），否则 `round(buy / 5)`；精炼和附加效果不提高卖价 | 只卖自己背包内未被占用的物品；已穿戴装备须先通过换装操作卸回背包，再另行出售；校验准确实例/数量和当前价格，整笔删除与加钱一起提交 |
| 打工 | 每次 100 体力换 500 金钱 | 按已有体力恢复规则刷新，再检查可用体力，扣 100 和加 500 同一短事务；不能花掉正式战斗预留体力 |

单件与批量使用同一套规则。装备购买生成指定数量的独立实例，初始无精炼、无附加效果；出售按明确实例列表处理，不能因界面分组而任意选走同种另一件。材料等可互换物品按数量处理。不迁移已注释的 1–10 次批量打工处理器。

正式商店基础编号为：1002、1003、1004、1100、1101、1200、1700、1701、1702、1703、1800、1801、2000、2001、3000、3001、3002、3100、3101、5000、5001、5002、5003、5100、5101、5102、5103、5200、5201、5202、5203、5500、5501、7000、7001、7500、8000、8009、8012。注释中的重置道具不因此加入商店。

重命名卡 7500 的买价和卖价均为 0，保留合法免费购买与零收入出售；其缺图按已有占位规则处理。这与“数量 0 免费获得非免费物品”的漏洞不同。物品数量、单价、乘积和累计金额必须处于可准确表示和存储的整数范围，越界整笔拒绝，不截断、回绕或静默封顶；接口专题统一数值表达和请求大小约束。

## 拍卖资格、标的与原有数值

持有拍卖会员卡 9000 才能新上架或出价。无卡时支付 11,000 获得一张卡，扣款与发卡同一事务；已经持卡不能重复缴费。资格以当前持卡状态判断，不改成终身账号权限。会员卡类型为“特殊”，不在可拍类型内；按原商店规则可卖得 100，卖后失去新交易资格，但已上架拍卖和已提交最高报价仍继续结算，不以结算时持卡为条件。再次入会仍付原费用。

| 项目 | 规则 |
| --- | --- |
| 可拍类型 | 剑、双手剑、匕首、魔杖、杖、弓、鞭、盾、书、甲、衣服、长袍、道具、材料；独立内容白名单，不从装备槽位推导 |
| 一笔标的 | 一种可互换堆叠物品及数量，或同一定义且精炼、附加效果等实际状态一致的若干明确装备实例；整批成交，不分拆竞买 |
| 上架费用 | 每笔 500，成功上架时扣；正常成交和流拍均不退，无额外成交抽成 |
| 可选时长 | 1、3、6、12、18、24 小时，界面默认 24 小时；初始结束时间为事务内上架时刻加所选时长 |
| 起拍价 | 非负整数，默认 0；是旧加价公式的初始基数，报价为整笔总价，不乘物品数量 |
| 最低下一价 | `p + max(100, floor(p / 10))`，其中 p 是当前最高报价，无报价时为起拍价；第一口同样必须加这一增量 |
| 出价资金 | 每次新最高报价全额从该买家钱包移入该拍卖的竞价款；同时将上一最高报价全额退回原买家钱包 |
| 身份限制 | 卖家与当前最高者不能出价；原最高者被超价并退款后可重新竞价 |
| 最后时段加价 | 成功出价时距截止不超过 900 秒且尚未到期，结束时间变为 `now + 900秒`；恰好剩余 900 秒不变，无延期次数上限 |
| 容量与频率 | 全服最多 100 笔未结拍卖，包含已到期但尚未结算的条目；同账号成功上架后满 30 秒可再次上架 |

例如起拍价 0，第一口至少 100；起拍价 1,000，第一口至少 1,100；当前价 1,010，下一口至少 1,111。界面同时显示起拍基数、是否已有报价及最低可接受报价，不能把无报价的基数显示成别人已经支付的出价。

旧完整物品编号编码精炼和附加效果，拍卖能够保留这些状态；新版改用已批准的独立实例身份，不能误写成旧拍卖丢失精炼或附加效果。上架后标的转入拍卖位置，不在可用背包中，不能使用、出售、穿戴、精炼或重复上架；结算、流拍、取消均移动原实例，不能重建并重抽状态。装备的批量分组只允许展示与实际状态完全一致的实例，不增加混合属性礼包。

## 原子操作与资金归属

交易模块管理拍卖状态和规则，资产模块管理钱包、竞价款、物品实例及位置、堆叠数量和体力。竞价款有明确拍卖归属，不能当作卖家可花余额，也不重复算作买家钱包；界面分别显示钱包可用金额和拍卖占用金额。不向交易模块复制第二份账号钱包。

每笔拍卖保存独立且不循环复用的身份、卖家稳定账号引用、准确标的、上架时刻、截止时刻、起拍基数、当前最高者/报价、已收费用、费用/加价/延期规则及其版本、状态和版本。状态为进行中、成交、流拍或管理员取消；进行中但已过截止时刻只能结算或按权限取消，界面显示“已截止，待结算”，不能因后台延迟继续接受报价。终态保留历史，不用删除记录表示结算。

| 命令 | 同一事务中完成的变化 | 失败与重试 |
| --- | --- | --- |
| 入会 | 再检查无卡、余额；扣 11,000、发 9000、记录流水 | 同请求重试返回原结果；并发新请求看到已有卡后不再收费 |
| 上架 | 检查功能/物品上架开关、持卡、标的可用、数值、费用、账号间隔及全服容量；扣费、移动全部标的、创建拍卖、记录间隔与流水 | 任一步失败不扣钱、不移物、不占位置、不更新间隔；相同实例不能同时归属两笔拍卖 |
| 出价 | 读当前拍卖及截止，检查持卡、身份、预期拍卖版本、最低价和可用金额；扣新全价、退旧全价、替换竞价款及最高者、必要时延时、追加流水 | 过期、页面版本过时、报价不足或金额不足均不扣钱；不自动提高报价；成功后丢响应仍可查回原结果 |
| 到期成交 | 检查未终结且到期；全部标的转给最高者，竞价款全额给卖家，清空该笔占款、记成交和各账号流水 | 不重扣买家钱；任何一步失败全部回滚，后续可按原拍卖重试 |
| 到期流拍 | 无最高者时原物退回卖家，记流拍及流水 | 不退款正常上架费；无人工领取步骤 |
| 管理员取消 | 检查权限、原因、预期版本及未终结；原物退卖家，当前竞价款退最高者，已收上架费退卖家，记取消与所有流水 | 与到期结算竞争，谁先提交终态谁生效；已终结不可再取消或再结算 |

所有命令遵守已有请求幂等与业务来源唯一性契约。客户端同次重试不能被当作新出价或新上架；后台结算按拍卖来源唯一，不依赖任务进程身份。提交结果、钱物、状态、各账号流水及幂等结果一并持久化。提交前崩溃无半笔变化，提交后丢响应只查询或重放结果；进程重启不能释放标的或竞价款。

竞价、到期和取消通过同一个拍卖状态的事务校验竞争。服务端时间在取得写入机会后读取，并用于该次截止检查和延期计算；事务外的请求到达时间不获得优先权。两名买家同时按同一页面出价，第一笔提交后，第二笔因版本变化失败并返回当前价格供重新确认，不暗中把第二人加价到新的最低价。

金币变化使用各账号当前余额的增量，不覆盖战斗、商店或其他拍卖刚产生的收入。交易不能使用正式战斗预留的资源，也不因账号正在战斗而一律阻止无冲突的购买或收款。结算不再检查买家会员资格、登录状态、卖家持卡或新内容的可上架条件。按[账号契约](accounts.md) Q10，停用只阻止新的玩家操作，不阻止已存在拍卖的成交、流拍、超价退款或管理员取消退款；相关钱物仍交付给原内部身份。

守恒示例：上架费 500 已扣，A 出价 1,000 后该笔竞价款为 1,000；B 出价 1,200 时，B 钱包减 1,200、A 钱包加 1,000、该笔竞价款变 1,200。成交再将 1,200 给卖家，B 不再扣钱。管理员取消则把 1,200 退 B、500 退卖家、原物退卖家；正常流拍只退物。除明确费用或商店/打工产出外，跨账号转移不能凭空增减钱物。

## 运行、账号与内容切换

到期任务按服务端时间发现应结拍卖并逐笔调用同一个结算操作；可重复执行，进程中断后从持久状态继续。任务晚执行只延迟到账，不延长出价窗口、不需要玩家上线领款或领物。异常拍卖保留未结状态和资金归属，暴露给运营重试或具名取消，不能丢弃，也不能阻塞其他可正常结算的拍卖。[运行方案](runtime.md) Q11 已确认每 5 秒扫描，正常运行以到期后 10 秒内结算为验收目标；重启或维护结束后立即扫描，保护性暂停不结算，维护/故障期间不承诺该时限。

首期开服提供可用拍卖功能，不继承旧样本配置的“暂停上架”作为新服默认。提供暂停全部新上架和 Q6 要求的按物品暂停上架；暂停上架不取消既有标的、不停止竞价、计时和正常结算，后端上架命令必须检查开关。旧总拍卖开关主要限制页面展示，竞价处理器并未可靠检查；[运营契约](operations.md) Q9 已确定日常总开关只暂停新上架，不提供独立暂停竞价；全服与按物品暂停任一命中即拒绝新上架，状态持久且操作留记录。内容维护暂停全部业务写入期间后台也暂停，恢复后处理已到期条目。

内容发布前检查实际未结拍品的定义及相关机制依赖，包括精炼、附加效果和装备许可，不能只比较基础物品 JSON。影响拍品属性、使用条件或使标的非法的更新，须先处理相关拍卖；不以“当前没人出价”为自动改动理由。与拍品无关的更新可继续，现有拍卖的条款和执行支持仍需兼容。紧急取消列表、原因、钱物退款和验证纳入显式迁移方案；不得只删拍卖记录来通过发布校验。更新生效后现有物品统一使用新定义，不为已售物品保留永久旧数值。

维护时长不补入截止时间。12:00 截止、11:55–12:05 维护的拍卖，恢复时按停服前持久保存的最高报价成交或流拍；不能先允许新竞价，再补跑到期任务。正常有效报价引起的最后 15 分钟延期仍照旧。

自助删号与新上架/竞价必须在相同账号有效性约束下竞争：不能删号检查通过后又接受新交易。仍有卖方条目或最高报价占款时拒绝删除；已终结历史保留稳定引用，历史展示及匿名化由账号/展示专题决定。显示名变更不改变拍卖归属。管理员删除也不能级联删除他人竞价款或拍品，先通过运营专题规定的业务操作解除义务。

管理员不得从界面任意改价格、最高者、归属或截止时间。需要纠错时查看拍卖和关联流水、对未结条目执行具名取消退款、或重试已到期结算；已终结资产修正通过运营专题的独立补偿操作记录，不改写历史成交结果。这里不授予提前强制成交能力。

## 后续验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 39 种商店商品、7500 零价格、精炼装备出售 | 覆盖正式目录和原定价格/取整；不自动新增注释商品；合法免费与零数量漏洞区分 |
| 0、负数、小数、混合字符串、越界金额、数量不足 | 明确拒绝且无任何资产变化；批量某项失败不部分成交 |
| 连续点击、跨设备入会或上架、两个买家竞争 | 同请求一次生效；会员费不会重复扣；账号 30 秒和全服 100 笔限制事务内生效 |
| 第一口、10% 舍入、整批标价 | 起拍 0→至少 100，1,000→1,100，1,010→1,111；数量不重复乘入报价 |
| 900 秒、899 秒、到期恰好相等 | 900 秒不变，899 秒补回 900 秒；相等拒绝，失败不延时、不退款旧出价者 |
| 到期扫描与新报价、取消同时发生 | 同一状态一次终结；有效提前竞价延时后扫描不误结；截止后不可补投 |
| A 被 B 超价，再由 A 出价；同账号双设备 | 全额扣退准确；当前最高者不能抬自己的价；过时页面拒绝，不自动加价 |
| 成交/退款同时收到战斗奖励或商店消费 | 当前余额增量正确，不能写回旧账号快照；预留资源不可被消费 |
| 各写入边界故障、成功丢响应、重复任务 | 钱物/状态/流水/请求结果原子一致；不丢物、不多退、不重复成交 |
| 无人出价、双方离线、卖掉会员卡、账号删除竞争 | 流拍/成交自动完成；持卡变化不撤销原交易；未结义务阻止删号 |
| 维护越过截止、进程重启、单笔异常 | 无延期或补投；恢复后只结一次；异常资金和标的保留，可追查且不拖住其他拍卖 |
| 发布改在售剑属性/附加机制、无关内容更新 | 前者阻止并要求处理受影响拍卖，后者兼容通过；不遗漏间接依赖 |
| 管理员重复取消、已成交后取消、与结算竞争 | 未结时一次退原物/全出价/原上架费，终态不能二次退款；无越权或无原因取消 |

证据修正：LEG-08 的未定义小写 `$now` 确为缺陷，但不能据此断言旧版立即到期；旧环境若把它按 0 参与运算，结果仍为当前时刻加时长。新版明确公式并消除未定义变量。普通失败上架/竞价虽然先在内存扣款，但外层只在成功时保存，不能声称所有失败都实际扣钱；需要替换的是分步持久化、混合请求和失败边界风险。
