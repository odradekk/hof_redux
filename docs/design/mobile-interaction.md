## 页面组织

玩家主导航保留冒险、角色、战报、城镇四项，手机主要页面持续可达；桌面沿用同一分区，可用更多横向空间，不能另造一套玩法或只在桌面提供必要操作。底部导航适配设备安全区域及软键盘，不采用原型为方案切换器留出的 `84px` 偏移。无进行中或可查看结果的状态时，不显示空的全局提示条。

| 区域 | 页面与必备入口 | 主要信息及操作 |
| --- | --- | --- |
| 登录前公共页面 | 登录、注册、恢复密码；公告、教程、手册、内容资料、公开竞技排行、正式战报、公共意见板 | 不因玩家主导航需要登录而封锁已批准的公开读取；需要登录/建队的写操作说明原因 |
| 首次建队 | 设置队伍名和首名角色 | 注册后未完成建队明确引导；不得把后来零角色的账号重新送入免费建队流程 |
| 冒险 | 地图列表、地图详情、成员选择入口、普通出战、团队模拟、原操作状态 | 进入资格、开放时段及部署时区、遭遇资料、成本、当前成员、记忆选择；不把地图预览当作预抽的下一场遭遇 |

| 战报 | 个人历史、公共列表、类型筛选、列表分页、详情摘要目录、逐步阅读及到期状态 | 摘要先行，每个战报步骤汇总关联事件和结束状态；支持前后翻页和步骤跳转，模拟可见性独立校验 |

| 城镇：共享玩法 | 拍卖列表/详情/上架/我的交易/历史，竞技排行/设队/挑战，世界 Boss 列表/详情/挑战 | 展示本玩法的资格、费用、冷却、共享忙碌与已提交状态；复用操作状态入口，不复用普通冒险的收费或结算规则 |
| 城镇：社区、资料与账号 | 两类留言、公告、职业/物品/技能/条件/怪物资料、手册、重复教程、外部论坛、账号设置 | 资料可按名称定位、分类浏览；长列表分页。帮助返回原操作页面，不丢未提交的战术草稿；外链明确标注，未配置则隐藏 |
| 独立管理后台 | 具名管理员登录、查询、管理操作、日志、任务状态、统计与诊断 | 与玩家角色培养页面分开；覆盖全部批准管理能力，见下文，不从玩家登录赋予管理员权限 |

主导航描述分区，不把培养做成每次出战必经的向导。账号相关入口在城镇中集中呈现；访客仍可直接访问公开页面。公共资料、公告、意见板、排行与战报的读取门槛按[展示契约](public-information.md)分别执行。

## 编队与角色培养

1. 从全部持有角色中选择培养对象，手机列表可横向浏览并提供定位选择，桌面可固定左列。角色数量不被五人出战上限限制；八人只是原型测试数据。
2. 明确显示姓名、职业、阵位、是否已选出战、是否正在编辑、正式战占用及未保存战术状态。只切换编辑对象不改变出战成员，离开并返回角色区保留编辑对象。
3. 编队勾选与培养切换采用不同控件。出战选择保持 1–5 人，第六人被拒绝并明确提示先换下成员；空队仍可浏览，提交出战时说明缺少角色。原子校验仍由服务器执行。
4. 出战顺序按角色模块的稳定列表顺序过滤，不能由勾选先后改变，不提供玩家拖拽重排。顺序有业务语义，并非“显示无关”。前后排属于角色配置；不增加固定格位或候补槽玩法。
5. 记忆队伍只保存成员，成功受理后生效；未受理不修改，后续故障取消不回滚。竞技名单单独展示与管理，不能把普通记忆当作竞技登记。
6. 培养页覆盖未分配属性、重置属性、职业与转职路径、技能及条件，不仅覆盖原型中的装备/战术/技能三个标签。招募、转职、改名和解雇展示合法目标、成本及影响；按既定规则处理装备及技能，不隐式添加自由换职或新成长机制。
7. 正式战只阻止被占用角色/装备的冲突修改，其他角色仍可培养。界面提示阻止原因，不能以全账号“处理中”为由锁住全部页面；团队只读模拟继续按独立占用规则处理。

依据：[内容模型](content-model.md)、[冒险流程](adventure-flow.md)、[事务契约](state-transactions.md)、[账号契约](accounts.md)。

## 战术草稿与保存

- 当前与备用仍为两个方案位置，交换保留原当前方案。草稿是未提交编辑，不是第三套可执行方案，也不自动成为战斗输入。
- 每角色分别保留草稿，仅限当前页面会话内存；切换角色、标签或页面不丢草稿。刷新、关闭可能丢失，浏览器允许时提示未保存；不承诺浏览器一定阻止关闭，不将战术草稿写入长期浏览器存储。密码与恢复码不作长期浏览器保存；登录会话 Cookie 沿用账号契约。
- 编辑明确显示未保存状态，提供保存及放弃未保存修改；成功保存后更新已保存视图。普通出战与团队模拟固定已保存方案，即使本地另有草稿。准备页提示所选角色存在未保存战术，但不静默保存或强制执行草稿。
- 保存与另一设备编辑冲突时保留本地草稿，展示需重新核对的状态；允许读取最新已保存值供核对，不自动覆盖任一方。HTTP 版本字段与精确同步协议归接口专题。
- 战术行按优先级从上到下显示。AND 组明确展示全部条件及行占用，作为整体移动；允许按合法条件和已学技能增删、编辑，禁止悬空连接或超容量添加。原型只用少量条件样例，不代表正式条件全集。
- 容量下降时隐藏超出部分，跨边界的完整 AND 组整体隐藏、不执行，配置仍保留；恢复容量后重新出现。不显示灰色超限规则，也不因保存可见部分删除隐藏配置。未配置或无条件命中时待机，不擅自补普通攻击。
- 交换当前/备用前先处理未保存草稿，不能让交换静默吞掉编辑；保存与交换都服从角色占用和版本校验。具体错误提示不把配置保存失败误称为模拟失败。
- “保存并单人测试”明确分别展示保存状态与测试状态。容量等受理检查未通过则不保存、不测试；已保存后演算故障不撤销保存，重试测试不能覆盖后来的角色编辑。

依据：[战斗契约](combat-contract.md)与[冒险流程](adventure-flow.md)。

## 装备、资产与交易

- 装备候选按武器、盾、甲、道具槽位筛选，提供名称定位。保留具体实例选择，即使名称、精炼和效果一致也不合并身份；允许界面分组，批量操作仍明确选中的具体实例。
- 不可装备候选可以查看，并说明职业、占槽、承载或占用原因，不把攻击数值变高当作可装备。比较当前与候选的实际属性、精炼、有序附加效果和占槽关系；不通过排序或合并效果改变其含义。
- 确认更换显示具体目标和所需卸装影响，提交由领域规则整笔验证；冲突不能静默卸下、出售或销毁其他装备。未找到候选时说明是筛选无结果还是未持有，而不是隐藏整个装备页。
- 技能页区分已学、可学和未满足条件；展示职业、等级、前置及技能点成本，提交前确认目标与扣点。学习成功后可进入战术编辑，不擅自插入战术或改变优先级。
- 背包、商店和工坊支持长列表、材料数量和实例详情。购买、出售、制作、精炼分别显示成本、产物及既定风险；精炼不可逆损失不得只藏在帮助页。连续精炼在游戏规则上逐次尝试，随机失败或余额不足时停止，展示实际次数、费用和最终装备状态；整批实际结果仍一次事务提交，存储错误全批回滚，不能误写成逐次落库或随机失败全批退款。
- 拍卖以整笔拍品和总报价为单位，显示上架费、最低加价、截止时间及时区、延期规则与当前最高价。数量须为明确正整数，提交前的金额预览不替代事务内检查。到期后即禁止竞价，未结算不能显示钱物已经到账。
- 上架暂停只阻止新上架，已有拍卖竞价和结算继续；维护时间不暗中延长拍卖。我的未结义务与删除账号阻塞原因可相互定位，不自动撤拍或退款。

依据：[交易契约](trading.md)、[内容模型](content-model.md)及[事务契约](state-transactions.md)。

## 战报与全局业务状态

战报列表展示模式、时间、双方及结果摘要，进入详情后先说明胜负和实际已提交收益，再按保存的事件顺序阅读。模拟明确无正式成长和资产收益；败北和平局不自动等于零收益。保留正式公开、模拟私有及 90/30 天默认期限，不提供玩家公开开关。

战报详情先展示摘要目录，按顺序列出每个战报步骤的摘要和关键变化，点选后进入独立的单步阅读页面。每页完整呈现本步骤的关联事件、数值前后变化及步骤结束后的双方阵型；一页允许纵向滚动，不以“一屏放下”为由缩小文字、裁掉单位或省略事件。手机和桌面采用同一阅读语义。战场版优先呈现行动者、目标和关键事件，双方前后排表达对峙关系；详细事件与前后数值可展开。单步收益显著标为计算收益，正式到账以整场结算为准；模拟和竞技中的临时收益不显示为可领取资产。待机、防御等没有数值变化的步骤仍明确显示动作和状态，不能留下空白事件区。

一个战报步骤对应一次行动推进及其关联事件：攻击造成的伤害、治疗、状态、死亡、召唤和收益记录按原执行顺序归入本次步骤，不把每条底层事件拆成一页。开始蓄力/咏唱是独立步骤，不与后来真正释放的行动合并；待机、失败也须保留。不能称为“全员行动一遍”的回合，步骤号不等于整场行动计数。开场/终场信息明确归在摘要或独立说明步骤中，不遗漏，也不伪装成角色行动。

提供“上一步／下一步”“第 N 步／共 M 步”和输入步骤号跳转。首尾不循环，越界或非整数输入明确拒绝且停留原步骤；切步后标题、关联事件、数值变化和阵型必须一起切换。焦点移到当前步骤标题并可被辅助阅读工具识别，表单编辑中的方向键不被抢占。返回目录恢复进入细读前的目录位置及来源条目，不能总回到目录顶部；切换另一份战报重新建立阅读位置。首期不增加滑杆、滑动手势、动画或完整未命中条件追踪。

事件格式需表达稳定顺序和明确的步骤归属，使跨伤害、死亡、召唤等事件的分组可核验；不能靠文字内容、相邻时间戳或当前规则猜分组。行动者、主动目标、事件类型及单次实际伤害/治疗须可明确读取；本步 HP 前后差值只表示净变化，不能据此反推出某次伤害或治疗。事件展示不从中文描述猜这些信息。生产记录已按战斗契约要求使用类型化事件；原型中的逐步 before/after 数组不构成每步持久保存两份完整快照的要求，只要求从已保存记录准确取得所选步骤的显示状态。保存/读取接口在后续接口专题细化，保持纯引擎与展示职责分离；页面只读取历史步骤及状态，不为翻页重新演算或重新抽样。事件与步骤总量仍受已确认的执行预算约束，具体预算由实施验证锁定，不用原型的 24 步代替正式上限。

阵型使用该场固定单位身份、素材和事件快照，今日改名、换装或改阵不改历史；同名怪物可区分。敌方及召唤数不限于五个，常规阵型展示步骤结束状态，死亡召唤物在死亡当步结束后即退出该阵型；死亡当步的事件展示保留目标形象并明确标记“本步阵亡”，完整事件和前后数值可读，后续步骤不重复显示本步死亡标记。这不改变战斗契约中的身份保留、统计或复活规则。展示与历史相关的素材缺失使用批准的占位策略，不能导致整份战报打不开。

| 状态 | 必须反馈与可操作入口 |
| --- | --- |
| 未受理 | 明确资格、容量、体力、占用或版本原因；不得显示本次新增了预留、冷却，或本次记忆/配置已保存；原有冷却和占用仍照实提示 |
| 响应未知 | 说明尚不能判断成功或失败，查询原操作；不能把再次点击变成新消费或新出战 |
| 已受理处理中 | 全局显示正式战、模拟各自状态，可进入原操作详情；离开页面、会话到期不取消业务 |
| 等待人工 | 保留原占用及预留并说明现状，不承诺固定倒计时后自动完成 |
| 成功完成 | 进入对应正式/模拟结果；仅已提交结果称为到账，不将演算收益先行加到钱包 |
| 故障取消 | 无胜负或收益，解除预留与占用；已受理时保存的配置或记忆不回滚 |
| 维护或保护性暂停 | 说明当前业务只读及已受理操作保留；保护原因可能并存，单一原因恢复不表示全部恢复 |
| 会话失效或灾难恢复代次变化 | 重新登录、刷新并核对当前状态，不自动重放旧购买/竞价/出战；管理员重新授权另走管理流程 |
| 战报过期/管理员清理/不可查询 | 文案区分状态，私有模拟先鉴权，不能借提示泄露其存在；不把展示清理当作结算撤销 |

世界 Boss 展示已提交的精确 HP/SP、当前轮次及冷却，忙碌不等于死亡，人数变化导致剩余值高于新上限时照实显示。竞技成员更换期限与主动挑战冷却分别说明，竞技全榜忙碌不能误写成个人冷却。依据：[展示契约](public-information.md)、[世界 Boss](world-boss.md)、[竞技场](arena.md)、[运行契约](runtime.md)。

## 账号、社区与管理流程

- 注册、登录、首次建队与恢复码展示分清业务步骤；密码规则、恢复码一次展示、响应丢失后的重新登录/重签发及全部会话退出按账号契约说明。密码允许粘贴，普通退出与退出全部设备按钮不能混淆。
- 零角色页提供打工和招募路径；解雇显示角色成长/技能损失及穿戴装备退回，并执行竞技及正式战保护。删号先展示范围、阻塞义务和不可自助恢复事实，再按契约校验密码及明确确认。
- 城镇留言、意见板、公告按各自权限呈现。留言显示字符限制、冷却、当时署名和允许的颜色；颜色不能成为识别作者或状态的唯一方式，也不能使文本在背景上不可读。玩家不出现编辑/撤回按钮，管理员隐藏不改写原文。
- 手册、教程和内容资料覆盖正式定义，相关页面有明确帮助入口；怪物资料公开准确掉落概率及动态属性口径，不泄露完整战术。论坛为外链；旧“无 JS 道具列表”由统一物品展示取代，不遗漏信息，也不保留旧浏览器模式。
- 管理后台覆盖账号停用/恢复/删除、资产补扣、成长/装备/名称修正、竞技修复、拍卖取消退款和上架暂停、故障恢复/取消、公告与留言管理、战报清理、IP 核查、统计、配置及内容只读核对。每项沿用[运营契约](operations.md)的范围，不增加任意改血、一键清榜或通用在线配置编辑器。
- 管理写入先预览对象、前后变化或固定批次范围，再提交原因及必要的近期密码验证；短操作在最终提交检查权限/版本，批任务显示已受理、运行进度和结果，不把部分批次成功称为全部完成。已受理固定范围任务不因管理员退出而扩大或撤销。

## 实施验收与本轮未验证项

以下是实施及上线前必须通过的验收要求，不是原型已经通过的事实。原议题的手机实际试用完成条件在用户确认收束本轮规划后移至该门槛，不能因规划议题关闭而省略。正式浏览器版本范围、接口分页大小及性能阈值在实施/验收专题锁定；记录设备、系统、浏览器、视口、操作场景、结果及未通过项，相关问题修复复验后才可宣称手机流程通过。

| 场景 | 检查内容 |
| --- | --- |
| 320/390/430 CSS 像素与桌面宽度 | 页面无非必要横向溢出；内容与确认按钮不被导航、软键盘或安全区域遮挡；长名称、数值、中文、零数据及错误可读 |
| 多于五名持有角色 | 可定位全部角色，编辑不改编队；换人不改变稳定出战顺序；同名角色仍能区分 |
| 多角色草稿与其他设备修改 | 各草稿互不覆盖；出战固定已保存配置；冲突保留草稿，刷新关闭的损失有明确说明 |
| 装备长列表与不合法候选 | 筛选、空结果、具体实例、占槽/承载/职业原因和原子失败清楚；键盘和触控均能完成选择与确认 |
| 长战报、多随从与召唤 | 目录定位、单步关联事件、前后翻页、非法跳转拒绝、返回原目录位置；蓄力与释放分别记录；召唤出现/死亡的前后状态一致，历史不依赖当前角色；正式/模拟权限及过期提示一致；不裁成五人 |
| 并发正式战/模拟及暂停 | 各状态入口可达，非冲突角色可操作，未知响应不产生重复业务，多原因保护正确 |
| 账号与零角色 | 首次建队、恢复码展示丢失、改密、会话到期、删号阻塞、解雇到零人的恢复路径均可完成 |
| 城镇与后台 | 原型中的摘要不能代替商店/工坊/拍卖/Boss/竞技/社区/管理的完整手机操作验收 |
| 基本可访问性 | 主要触控目标至少 44×44 CSS 像素，文字可缩放、键盘焦点可见、字段有标签、状态不只依赖颜色；重要错误不能只显示短暂浮层 |

原型控件没有生产权限或持久化能力；示例素材、武器数量、条件容量、战报步骤及结果均不作为正式玩法定义。图标素材复用有来源记录，正式界面布局与代码重写。真实手机触控、软键盘、视觉对比及关键流程测试未完成时，不宣称上线条件满足。
