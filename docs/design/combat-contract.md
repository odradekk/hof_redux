## 输入输出边界

- 引擎接收双方初始战斗快照、模式规则、不可变内容/规则快照和可注入的随机源；不访问数据库、HTTP、真实时钟或页面。
- 输入保存确定的队伍遍历顺序与战斗单位身份。玩家角色身份与本场战斗单位身份分开；召唤单位也有本场稳定身份。
- 输出包含胜负与终止原因、最终战斗状态、成长/收益计算结果及有序事件。输出是计算结果，不表示资源已经写入账号或共享 Boss 状态；外层按模式执行事务结算。
- 随机源覆盖同速选择、目标、护卫顺序与概率、状态概率和随机召唤。验证可提供明确随机输入序列；不使用系统时间重复播种。不因“结果看似相同”而擅自删除旧有抽样步骤，已批准概率修复需登记对应抽样映射。
- 保存引擎版本、规则/内容版本、随机算法版本及复现所需输入。历史战报通过已存事件展示；重新演算必须使用对应版本和输入，不能只凭一个旧种子交给新规则重算。
- 普通事件与诊断追踪分开。事件至少有顺序号、类型、行动者/目标引用和对应类型的结果字段；伤害区分计算值与实际 HP/SP 变化，避免吸取、屏障和过量伤害的含义混淆。追踪开关不能改变演算结果或随机调用序列。
- 非法输入、内容缺失、数值异常或执行保护限额耗尽是演算错误，不能伪装为正常平局。具体限额依据机制边界制定；模式的正常行动上限与程序保护限额分开。

执行保护按可复现的工作量计量（调度步骤、目标效果执行次数、创建单位数、事件数），配置及版本纳入输入和复现包。[运行方案](runtime.md) 要求结合正式内容和处理器边界形成预算依据，在最坏合法组合及故障注入验证后锁定，未通过不得上线；不得使用实际耗时作为游戏胜负规则。进程超时或取消属于外层运行失败，同样不结算成平局。

## 演算接口

以下是领域契约，不固定 TypeScript 名称、数据库表或 HTTP 格式。

| 输入 | 必须包含的含义 |
| --- | --- |
| 规则标识 | 引擎语义版本、内容快照版本、模式及行动条规则；均对应不可变内容 |
| 双方快照 | 有序成员、本场单位 ID、角色来源引用、有效属性与装备/被动效果、等级/经验/成长点、初始 HP/SP/状态/阵位、有效战术、保护策略及奖励定义引用 |
| 模式数据 | 行动上限与超时规则；Boss 使用当次有效的共享状态和已求值的动态属性，不能在引擎中读取在线人数 |
| 随机输入 | 算法版本与初始状态，或测试提供的有类型、有范围的随机操作结果序列 |

引擎校验引用、状态和数值后复制输入，不修改调用者快照。战斗中使用的有效属性已按内容模型计算；引擎仍保留技能可能读取的等级、装备效果等来源信息，不能只输入最终攻击力。新召唤单位按同一版本内容构建。

成功输出包含：胜方或平局、终止原因（全灭、双方全灭、行动上限）、整场行动计数、双方最终战斗状态、逐角色成长变化、双方收益明细、有序事件及复现信息。每项经验或掉落须能关联产生它的事件；战斗临时 HP/SP、毒、阵位和召唤状态不自动成为角色持久状态。

失败输出包含错误类型、阶段与诊断引用，不产生可领取收益。事务层决定如何处理已预留的成本及重试，不由引擎自行扣款、回滚数据库或发布战报。模拟和竞技的中间成长计算与可持久结算资格分开，不能为了“不给奖励”而改变会影响同场战斗的演算。

## 行动时间与三个计数

两种行动条模式均实现，首期沿用模式 1。队伍与成员顺序是规则输入，不能排序后再演算。

| 规则 | 模式 0 | 模式 1 |
| --- | --- | --- |
| 重置 | 行动条设为 SPD | 行动条设为 0 |
| 推进与选择 | 基准为最大 SPD + 平均 SPD × 2.5；选择当前行动条最大者。按队伍 0、队伍 1 顺序扫描，每遇并列者抽一次二选一，不改成并列者均匀抽样 | 速度率为 `sqrt(SPD)+5`；选择 `(100-delay)/速度率` 最小者，精确并列者按一次随机选择处理 |
| 全员推进 | 基准与选中者的差值非负才推进 | 所需距离非负才推进；死者不推进 |
| 速度变动 | 按旧时机重算全局基准 | 后续计算使用新的 SPD，不重算全局基准 |
| 前摇、后摇及延迟效果 | 减少 `(基准-SPD)×rate/100` | 普通单位减少 rate；世界 Boss 减少 `round(rate/3)` |

不得用误差容忍窗口合并原本不相等的行动时间。具体数值实现通过公式和旧运行样例校验，避免语言迁移改变行动次序。

| 计数 | 增加时机 | 不应误解为 |
| --- | --- | --- |
| 整场行动计数 | 选定战术或待机后增加；技能失败仍占用；开始蓄力/咏唱时撤销这次增加 | 全员轮流行动一遍的“回合” |
| 单位技能使用计数（旧 ActCount） | 越过武器、SP 和开始蓄力检查后、检查魔法阵之前增加 | 成功命中次数；魔法阵不足也会增加 |
| 战术行命中计数（旧 JdgCount） | 条件组成立后，组内每行分别增加，在技能使用检查之前 | 技能成功次数；施放失败不退回 |

蓄力开始虽不消耗整场行动额度，仍产生独立事件。程序执行预算还需覆盖这些步骤，不能仅靠整场行动上限防止异常循环。

## 战术、条件与目标

角色容量按旧 `MaxPatterns` 公式计算。当前/备用方案仍各自保留完整配置；只有当前方案容量内完整的条件组参加战斗。编辑入口不让玩家新增超容量行；容量下降后隐藏尾部，恢复后重新出现。空方案和无命中统一走正常行动开始阶段及待机流程。

按行从前往后寻找首个成立的规则。连续连接动作（旧 action=9000）与其后实际动作组成 AND 组，条件从左到右短路；组合末尾必须有实际动作，保存和内容发布时拒绝悬空连接。命中的条件只决定是否选用动作，不把条件判断过程中找到的单位隐式绑定为技能目标。蓄力完成不重新判断战术，也不沿用开始蓄力时的目标。

| 条件族 | 参数与语义 |
| --- | --- |
| 常真/跳过、自身中毒/阵位 | 无数量参数 |
| 当前/最大 HP、SP 的绝对值；人数、魔法阵数、触发次数 | 非负整数；比较方向及等号按原条件定义。人数不能限制为五人，召唤会扩大队伍 |
| 自身或团队 HP/SP 比例、毒比例、概率 | 百分比 0–100；团队平均排除死者，SP 平均另排除 MAXSP=0 的单位；使用各条件原有分母与舍入位置 |
| 存活、死亡、前后排、蓄力、咏唱、召唤数量 | 各自明确候选资格，不使用一个通用“人数”函数替代全部语义 |
| 单位行动序数 | 保留旧 ActCount 与 `quantity-1` 的比较，玩家输入从 1 起算 |
| 本行触发次数 | 使用本行计数，与 AND 组中其他行分别保存 |

已确认的敌方毒比例条件修正为 1617/1618。条件 1506 的“己方咏唱人数以下”错误读取蓄力人数，按明确笔误规则修为 CAST（LEG-18）。未开放且无实现的属性条件 1300–1381 不补造效果。正常行动者必然存活，团队 HP 平均不存在零存活的正常行动路径；输入校验及函数前置条件处理非法调用，不将其宣称为已证实的玩家缺陷。

目标阵营为己方、敌方、自身或按己方再敌方拼接的双方。单体模式先选一次目标及保护者，再对同一目标执行多段；随机多目标模式每段重新选择，允许重复；全体按候选顺序、逐个目标完成全部段数，不触发保护。

普通目标排除死者；低 HP 比例、后排、死者、召唤物、蓄力/咏唱者等优先选择沿用各分支。后排候选为空时回退普通随机；死者、召唤或蓄力候选不存在时不能改成普通攻击目标。召唤优先分支包含死亡召唤物，不能把普通目标的死亡过滤提前应用于所有分支；被选中不等于复活。复活按 Q7 过滤可复活死者，无目标也不退还已经支付的施放成本。

技能标记为无视保护或支援、原目标在前排时不触发保护。其余从同一目标候选阵营中筛选前排、非死亡且 HP>1 的单位，洗牌后逐个判断保护策略，第一个成功者替换本次目标；不改变后续选取池。未知保护策略由输入校验拒绝，不能落入旧默认必定保护。LEG-13 修正概率与 HP 边界，其他资格和抽选顺序保留。

## 一次行动的阶段顺序

1. 选行动者并推进时间。没有待完成蓄力/咏唱时，先持续回复，再承受非致死毒伤，然后判断战术；待完成时直接使用记录的技能，不额外触发持续回复、毒伤或战术判定。
2. 按前述位置记数。未选到动作则待机并正常重置行动条。选到动作后，先检查武器许可（旧怪物豁免仍保留），再检查 SP。失败重置行动条；SP 不足还清除待完成技能。
3. 需要前摇且尚未蓄力时，记录技能及蓄力/咏唱类型、施加前摇，撤销本次整场行动计数，结束这一步；尚未支付 SP/HP，也未锁定目标。
4. 真正施放先增加单位技能使用计数，再检查并消耗己方魔法阵。魔法阵不足只重置行动条，保留已有蓄力以便后续重试；此时不扣 SP/HP。通过后扣 SP、清除蓄力，再支付可致死的 HP 牺牲。
5. 选择目标与保护，按目标模式逐段执行效果。全部目标结束后处理使用者的 `umove` 位移。HP 降至零与死亡标记分开；不能提前终止剩余段数。
6. 若有牺牲先判使用者死亡；此检查调用掉落计算并消耗相应随机操作，但其收益返回值被丢弃，不发给任何队伍。再按候选顺序判死与产生经验、金钱、物品，只有这一候选检查返回的收益用于队伍经验、物品、金钱累计。即时成长只改变旧时机本来改变的等级、经验和点数，不附送满血或重建全套战斗属性。
7. 需要时重算模式 0 基准，正常重置后应用后摇，检查全灭与行动上限。

武器在本场没有正常变更路径；完成蓄力时武器不符的旧分支不作为新玩法开放。若未来引入换武器机制，应重新定义该失败状态，不能从当前未使用路径推导新系统规则。

## 效果与特殊机制覆盖

通用效果使用有类型的参数与明确执行顺序，特殊技能引用具名处理器；处理器只能操作传入的战斗状态、随机源和事件记录器，不能持有数据库或账号写入能力。内容字段出现顺序不决定执行顺序，迁移也不能把叠加效果排序或去重。

旧通用路径每个目标、每段依次处理：增加己方魔法阵 → 删除敌阵 → 持续回复标记 → 蓄力目标门槛 → 召唤 → 解毒 → pow 伤害/治疗 → SP 回复 → 中毒 → 击退 → 数值状态变化 → 目标位移 → 行动延迟。召唤分支创建有序单位后提前返回，跳过后续效果；前面的阵和持续回复已经发生。通用字段仅在该技能实际走通用路径时有效，具名处理器不默认再跑通用路径。

已核对两个容易误迁移的组合：默认 support+pow 路径会双次调用状态变化，但唯一同时带治疗和状态字段的现有技能 5022 走专用分支，实际只变化一次；新版不得把它迁成双次增益，也不需要为当前不存在的组合复刻重复调用。现有增删阵技能 3410/3411/3415/3420/3421 均为自身单目标单段，每次施放仅一次；未来多目标增删阵的语义须明确，不能由旧循环位置意外决定。

| 机制族 | 处理方式与代表旧编号 |
| --- | --- |
| HP 伤害/治疗、多段与范围、SP 回复、持续回复 | 通用效果；目标方式与效果分开，伤害类型和 pow 显式化 |
| 毒、解毒、毒抗；属性/双攻/双防/上限的定值与百分比变化 | 通用有序效果；每步立即取整。毒按 LEG-16 |
| SP/HP/魔法阵成本、前摇/后摇、武器条件 | 行动阶段规则，不能混入目标效果后再扣费 |
| 位移、击退、延迟、阵增加/删除 | 通用效果；使用者位移处于整次技能结尾 |
| 召唤、速攻、召唤强度、被动面板 | 通用创建/派生规则；本场新单位加入队尾并取得独立身份 |
| HP/SP 双边平分 | 具名处理器，1024/1025；保留方向不对称的上限 |
| 阵位、损失 HP、中毒、死亡数量倍率 | 具名处理器，1022/1023、1116、1200、2055 |
| SP 攻击、HP/SP 同伤、吸取 | 具名处理器，1020/1021、2030/2031、2090/2091、5002；吸取按请求值恢复 |
| 毒爆、毒转属性、即死、自毒/自伤 | 具名处理器，1208/1209、2032、3900/3901 |
| 复活、变身、屏障 | 具名处理器，2056/2057、3040/5030/5063、3060/5067；目标资格按 LEG-17 |
| HP/SP 比例转换、上限增长、固定/缺血治疗 | 具名处理器，3010–3013、3020、3120–3122 |
| 蓄力干预、提前行动、咏唱延迟 | 具名处理器，2110/2111、3050、3055 |
| 召唤限定增益、随机特召 | 具名处理器，3300–3310、5803；随机特召保留五项候选 |
| 重置阵型、拉动目标、攻防转移、禁止自用的治疗增益 | 具名处理器，4000、5006、5060、5022 |

技能 3113 空处理器、7000/7001 的小写被动字段没有查到正式职业学习或怪物引用；按未开放定义保留，不凭空补全。HealBonus 仅有预留加载，没有实际内容与治疗接入；hit/stiff/strict 仅见注释或模板，不扩充为新机制。内容发布议题负责逐条 268 个唯一技能的机制映射、可达性及机器校验，本表覆盖机制族，不冒充逐条迁移完成。

## 数值、随机与默认保留的边缘规则

| 数值 | 运算顺序 |
| --- | --- |
| 基础伤害 | `(sqrt(依赖属性)×10 + ATK或MATK)×pow/100×特殊倍率`；物理默认依赖 STR，`inf=dex` 改用 DEX，魔法依赖 INT。屏障处理后取该值的 10% 作最低伤害；非无视防御时依次应用百分比、固定防御；加特殊 Pierce×pow/100；抬至最低值；最后 ceil |
| 基础治疗 | `ceil((sqrt(INT)×10+MATK)×pow/100)`，再按目标上限限制实际回复 |
| 毒伤 | `round(MAXHP×0.1)+ceil(level/2)`，乘毒伤倍率后 round，非致死最低保留 1 HP |
| HP 牺牲 | `ceil(MAXHP×百分比/100)`，使用者后排再乘 2，可致死 |
| 属性状态 | 每步按旧 round/floor 执行；双防增加按距 100 的剩余部分 floor，减少按当前值 round，不能合并后统一取整 |
| 召唤强度 | `1+(sqrt(DEX)×5+LUK)/250`，再应用召唤加成，创建时对 HP/SP、五维与双攻逐项 round |
| 经验 | 总经验先乘 EXP_RATE 并 round，再除以非召唤存活人数并 ceil；无合格者不发放；角色按已批准连续升级规则即时处理 |

round 在正负半值处的规则、整数范围和中间值由公式契约明确验证，不能直接用 JavaScript 的同名函数假定等价。无效数值、非有限结果及不支持的溢出作为演算错误；普通 HP 过量伤害不属于程序数值溢出。

随机调用点包括行动并列、目标选择、保护候选洗牌及概率、战术概率、毒抗/中毒、即死、随机召唤以及奖励掉落。测试随机源按操作（整数区间、候选选择、排列）供给结果，不能把 PHP 库内部随机算法当作迁移契约。诊断记录调用序号、用途和范围，可识别额外或缺失抽样。

LEG-13 的保护仍使用原概率调用点，修正比较边界。旧 life25/50/75 的 HP 保护同样消耗一次 1–100 抽样，虽然是否保护只看 HP；按抽样次数保真原则保留该操作，不重复播种，也不把这个未使用值用于决定保护。LEG-16 保留已经中毒时直接返回；有毒抗保持 `randomInt(0,99) < 基础概率×(1-毒抗/100)`；无毒抗且基础概率不足 100 时新增一次同范围抽样，100% 沿用无抽样的确定成功路径。新增抽样是批准修复所需差异，样例不得要求修复前后整场随机序列自然保持对齐。

以下按保真基准默认保留，并非此次新增设计：魔法阵不足保留咏唱；屏障置零后特殊 Pierce 仍可能造成伤害；平分 HP/SP 的上限仅在使用者较低方向生效；吸取按计算请求量而非实际扣除量恢复；经验向上均分可能增加总发放量；多段结束才标记死亡。统计展示应区分计算值和实际变化，不沿用旧 HTML 函数的混合返回值作为真实伤害。

## 死亡、召唤与四种模式

死亡单位停止行动与行动条推进、清除蓄力。死亡召唤物保留身份：不计存活、不分经验、不作为竞技超时存活人数、不参与普通展示及复活；仍计入旧召唤数量和相关死亡数量条件。旧 CountDead 还把带 Undead 特性的存活者计入特定死亡数量计算；不得把“可复活死者”用作所有死亡统计的统一集合。

每个候选先处理 Boss 本次 HP 差经验，再判新死亡。新死亡依次计算经验、金钱、掉落；持续处于死亡状态不会重复触发死亡奖励，复活后再次死亡按旧规则重新判断，不能增加“一场每个单位最多奖励一次”的新限制。牺牲检查与候选检查的收益去向按行动阶段区分：正式怪物也会用牺牲技能，其牺牲死亡的掉落计算不会成为敌方收益，不能以“死亡都发奖”统一改写。Boss 保留按 HP 差经验与击杀 DropExp 两条来源，不合并成只发一次的奖励公式。共享 Boss 能否成功提交以及其他并发挑战能否领取击杀奖励属于外层事务契约。

[Boss 专题](world-boss.md)补充核对发现复活后的 LastHP 初始化错误（LEG-26）：新版以本场实际起始 HP 作为差额基准，避免首次包含 Boss 的候选检查前已受伤时漏计经验。该修复不改变候选检查、差额公式与死亡奖励的顺序。

| 模式 | 引擎终止规则 | 外层职责 |
| --- | --- | --- |
| 普通战 | 100 行动，当前封顶也是 100，超时平局 | 1 体力；提交角色成长与本场收益 |
| 模拟战 | 镜像队伍；团队模拟 50 行动，角色战术页单人试战 10 行动，均禁止延长，仍计算正常胜负 | 不收体力，不持久化战斗产生的角色或资产收益；玩家主动保存的战术/记忆队伍按冒险流程处理 |
| 竞技场 | 100 行动；超时比较非召唤存活者，多者胜，同数平局 | 不提交战斗成长和掉落；排名与冷却由竞技场模块处理 |
| 世界 Boss | 100 行动，超时平局；Boss 延迟与差额经验规则如上 | 10 体力、20 分钟限制；提交玩家成长/收益与共享状态，处理冲突、击杀及复活 |

每步先判全灭，再判行动上限；同时全灭为平局。正式胜负的存活统计与竞技超时的非召唤统计分开。旧延长分支在当前上限配置下不可触发，不据此提高首期上限。普通角色每场初始状态与战后持久化继续遵守内容模型，不能把本场死亡作为账号角色永久死亡。

单人试战上限是冒险入口核对补充的旧事实：`class.main.php:471–486,1114–1144` 的“设置 & 测试”使用默认 10，团队 `:1164` 显式传入 50；不是把旧单人上限从 50 改为 10。入口与保存语义见[冒险流程](adventure-flow.md)。

## 事件与复现

事件使用结构化类型，不携带拼接 HTML。公共字段为连续事件序号、行动步骤引用、类型；有行动者/目标的事件携带本场单位 ID。整场行动计数可能不增长，不能拿它当唯一事件 ID。原因字段使用稳定标识，展示层再生成中文文案。

| 事件族 | 必要信息 |
| --- | --- |
| 行动、待机、技能失败、开始/完成/中断蓄力 | 行动者、技能、命中的战术组/行、计数变化；空方案/无命中/SP不足/魔法阵不足等原因 |
| 选目标与保护 | 原目标、最终目标、保护者及触发策略；无合格目标原因 |
| 成本、HP/SP 与数值属性变化 | 来源技能及段次、计算请求值、前后值与实际变化，区分牺牲/毒伤/攻击/回复 |
| 毒、屏障、持续回复、阵位、行动条、魔法阵 | 增加/消耗/清除的状态与前后变化、产生原因 |
| 召唤、死亡、复活、变身 | 单位身份、来源及状态变化；召唤含构建后的显示所需初始状态 |
| 成长与收益 | 来源事件、受益者、经验/等级/点数变化及计算出的资产收益；不宣称已经入账 |
| 结束 | 胜负、原因、行动计数和模式所需结果；提交状态由外层补充 |

普通战报必须足够展示实际过程与关键原因，手机端可折叠动作和多段，但不得修改事件。完整条件失败、候选过滤、中间公式、随机调用放在可选诊断追踪；两种记录级别得到同样结果。战报总伤害按明确事件含义计算，不让技能返回 true/数字的历史差异污染统计。

复现包包含规范化初始快照、输入顺序、初始随机状态、引擎/内容/随机算法/事件格式版本，以及快照完整性标识。历史展示依赖已存事件与显示快照；复算需要原版本执行物和内容，缺少时明确不可复算，不静默使用新版。[运行方案](runtime.md) Q22 已确认内部正常正式战 90 天、模拟战 30 天、故障取消后 30 天，在途输入及仍被依赖的执行物持续保留；管理员提前清理可见详情不提前清理内部复现材料。可见性和 Boss 公开数值按[展示契约](public-information.md)，内部可复现数据不能直接作为公开战报接口。
