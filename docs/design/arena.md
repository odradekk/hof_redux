# 竞技场防守快照与挑战结算

状态：已确认。Q1–Q7 及 Q8 完整契约均经用户确认。对应[确定竞技场防守快照与挑战结算](https://github.com/odradekk/hof_redux/issues/11)。本文件是规划，不表示竞技场实现、并发测试或运行验证已经完成。

前置：[战斗契约](combat-contract.md)、[状态与事务契约](state-transactions.md)、[内容模型](content-model.md)、[内容发布](content-release.md)及[保真基准](../legacy/fidelity-decisions.md)。正式依据是 `class.rank2.php`，不混入备用 `class.rank.php` 的不同规则；不增加积分、赛季、奖励排行、玩家指定对手或独立攻防名单。

## 已确认的裁决

- Q1：48 小时只限制重新登记竞技成员；攻防共用名单，每场成功受理时固定双方当时最新的成长、职业、装备、技能、战术等状态。登记不冻结数值，受理后的修改不改变本场。
- Q2：整个竞技场同时只受理一场正式挑战；忙时其他新挑战直接拒绝，不排队、不产生冷却。演算在数据库写事务之外，全榜占用为持久业务状态。
- Q3：主动挑战冷却从成功结算事务内的服务端时刻起算，胜利 1 分钟，失败或平局 24 小时；系统故障最终取消不产生本次冷却。防守不修改自己的主动挑战冷却。
- Q4：当前竞技名单中的角色不能直接删除；先在允许重新设队时将其换出，再按角色删除规则操作。不继承删除后静默缺员的旧行为。
- Q5：保留榜外玩家只有获胜才正式入榜的规则；败北或平局仍在榜外，但双方正常记战绩，挑战者产生 24 小时冷却。空榜首次有效挑战无战登顶的特殊规则保留。
- Q6：有已受理竞技挑战时，拒绝任何会删除或重排榜单成员的操作，包含榜内第三人删号；其他无冲突操作仍可进行。榜外且无其他占用的账号不因这条规则被禁止删除。
- Q7：榜内对手账号不存在，或竞技名单有失效成员时，拒绝本次挑战，不记战绩、不产生冷却、不自动换对手或修改名次；记录异常并交运营修复。无在途竞技挑战时，管理员可修复或具名移除无效榜内账号，按原顺序补位。

## 竞技名单与每场状态

竞技名单由账号拥有的 1–5 个互不重复角色组成。首次登记即可完成；成功登记记录服务端时刻，满 48 小时可再次登记，包含恰好相等的边界。登记成功不自动入榜，不改变已有名次或主动挑战冷却。合法新登记即更新登记时刻，包括主动再次提交相同名单；同一请求的幂等重试只返回原结果，不刷新时刻。

登记只保存角色身份和成员顺序：按角色模块提供的稳定列表顺序过滤所选成员，与旧入口遍历账号角色列表一致，不按勾选先后、HTTP 字段枚举或无序数据库查询排列。保存的顺序用于后续对局快照，不增加拖拽重排或手动速度优先权，行动和同速规则沿用战斗契约。普通冒险的记忆队伍与竞技名单相互独立；修改其中之一不覆盖另一个。

角色模块对删除操作检查竞技名单引用；更换名单、删除角色与主动战斗占用在同一事务规则下校验，不能先查无引用再并发加入或删除。即使 48 小时已经过期，只要仍在当前竞技名单中，也必须先换出。此规则不意味着玩家不能删除整个账号；账号删除按榜单及其他未结义务处理。

每场受理从双方当前已提交状态生成不可变的竞技对局快照，包含实际角色数据、物品定义和实例状态、技能/战术、阵位/保护、显示名、规则版本及随机初始状态。普通角色初始 HP/SP、状态与成长的演算遵守通用战斗契约。不能只保存指向实时角色的引用，也不能重新读取登记时旧数值。

主动挑战者遵守通用正式战斗占用：账号不能另开正式战，出战角色和装备的冲突修改被拒绝，候补及无冲突资产可操作。防守快照不占用守方角色和装备，也不冻结守方账号；守方可以有正在进行的普通冒险或 Boss 战，本场读取其已提交状态，不读取另一场尚未提交的演算成长。受理后守方继续成长、换装、改战术，甚至在 48 小时已到时重新登记成员，都不改变本场输入或取消本场结果。

满 48 小时后，攻守双方都可登记仅供未来对局使用的新名单，本场快照保持不变。主动方将某角色换出未来名单，不解除该角色及装备在本场的占用；本场终结前仍不能对其作冲突修改或删除。名单引用与在途战斗占用是两项独立校验，不能用一项解除另一项。

名单改变后已换出的守方角色，可在满足角色删除规则时删除；本场已有完整快照，不再要求该角色实体继续存在。守方账号仍在榜，删号则受 Q6 阻止。防守角色的后续版本不作为结算冲突条件；结算只增量更新守方竞技战绩，不把快照中的角色、装备或整份账号状态写回。

## 榜单结构、挑战与入榜

排名采用有序槽位分档，而非一人独占一个显示名次。第 1 档容量 1，第 2 档容量 2，第 3 档及以后每档容量 3；档位以第 1、第 2、第 3 名等显示，同档玩家名次相同。只有末档允许不满，榜单无空档，账号不重复。档内顺序是稳定的补位顺序，不额外赋予同档不同显示名次。

| 当前状态 | 有效挑战的处理 |
| --- | --- |
| 尚未登记有效竞技名单 | 拒绝，不入榜、不产生战绩或冷却 |
| 主动挑战冷却未到、账号已有主动正式战，或竞技场正在处理挑战 | 拒绝并给出对应原因；原请求重试仍查询原操作 |
| 空榜 | 第一个通过资格校验的挑战者原子成为第 1 名；无对手、无战斗、无战报、无战绩、无挑战冷却 |
| 已是第 1 名 | 拒绝主动挑战；可以继续防守、培养角色或按登记间隔换队 |
| 已入榜且不在第 1 档 | 从自己上一档的全部成员中等概率选一人，不能自行指定或挑战同档 |
| 尚未入榜，榜单非空 | 计算临时榜尾槽位：末档有空位则使用该档，否则追加下一档；从该临时档的上一档等概率选一人 |

名单登记与榜单报名不是两个新增收费动作。玩家仍通过原有“挑战”动作尝试入榜；空榜时界面明确提示这是无对手入榜，不伪造一场获胜。两个账号并发争空榜，只有先提交者无战登顶；另一个按随后真实榜单进入正常挑战，不能同时成为第 1 名。

对手选择在受理事务中基于确定的榜单版本和候选顺序完成；记录所选对手、双方槽位、榜外挑战者的临时槽位及恢复需要的随机输入。不能排除离线、主动冷却中或正在其他玩法战斗的有效守方。若选中对手的数据无效，按 Q7 拒绝并记录，不跳过后重新抽人；候选档为空或榜单结构不合法同样是异常，不创建虚构胜利。

榜外挑战者的临时槽位只属于本次操作，受理时不把它写成正式榜内成员。成功结算获胜时，先将其加入临时榜尾槽位，再与对手交换具体槽位，一次提交；败北、平局或故障取消均不留下新排名条目。战报保存本场使用的“榜外挑战者/临时档位”与对手信息，不能把临时槽位显示成已正式入榜。

## 结果、战绩与冷却

使用纯战斗引擎的竞技模式：100 行动上限；先判全灭，再判上限；超时比较非召唤角色存活数，多者胜，同数平局。LEG-03 的变量错误按已批准决定修复。未知结果或演算异常不能降级成平局并给玩家 24 小时冷却，应进入通用故障恢复/取消流程。

竞技不收体力、金钱或物品，不产生货币、掉落或可持久角色成长。引擎内部仍按既定顺序计算会影响本场的效果和成长，但只结算竞技排名、战绩、主动冷却和正式战报；不因竞技死亡永久删除角色，不把临时 HP/SP 写回。

| 正常结果 | 排名变化 | 双方战绩 | 挑战者下次可挑战时刻 |
| --- | --- | --- | --- |
| 挑战者胜 | 仅交换双方具体槽位；若挑战者榜外，先按本场临时槽位加入再交换 | 双方总场次各 +1；挑战者胜 +1，守方负 +1 | 成功结算时刻 +60 秒 |
| 守方胜 | 原排名不变，榜外挑战者仍榜外 | 双方总场次各 +1；挑战者负 +1，守方胜 +1 | 成功结算时刻 +24 小时 |
| 平局 | 原排名不变，榜外挑战者仍榜外 | 双方总场次各 +1，双方平局各 +1 | 成功结算时刻 +24 小时 |

旧 `defend` 是累计成功守冠次数：守方在第 1 档且本场胜或平时 +1，其他防守不加；它不是全部防守场次、连续守冠次数或只计胜利的计数。失败丢掉第 1 名不清零此前累计值。总场次包含主动和被动对局，满足总场次 = 胜 + 负 + 平；空榜入榜、无效挑战和故障取消不计数。

例如 A 第 1 名，B/C 并列第 2，D/E/F 并列第 3。D 挑中 B 并获胜后，D/C 第 2，B/E/F 第 3，A 不变。若 G 原本榜外，其临时位置是第 4 档，挑战上一档的 E 获胜后 G 进入 E 原槽位、E 到第 4 档；G 败或平则依旧榜外。

冷却只约束主动挑战，不限制被动防守，不因防守战绩变化重置。下一次挑战允许时刻比较包含等号，名单重设的 48 小时与主动挑战的 1 分钟/24 小时分别计算。未终结主动战仍受占用限制，不能因时钟经过而另开正式战。断线、重启或恢复执行不重置受理输入，Q3 的冷却只在最终成功结算时确定。

## 事务、占用与失败恢复

竞技场模块负责名单登记元数据、榜单/版本、挑战记录、双方竞技战绩和冷却；角色与物品状态仍由所属模块提供。一个榜单上的未终结挑战占用唯一，全榜读取不需要长期写锁。展示只返回已提交榜单，可显示“竞技挑战处理中”，不暴露未确认临时名次。

1. **登记事务**：校验账号可操作、预期名单版本、48 小时边界、1–5 个有效自有成员；一次保存名单、登记时间和操作结果。攻守双方在对局期间合法登记未来名单，不修改榜单槽位、已受理输入或本场主动方角色/装备占用，不能因已有对局一律禁止登记。
2. **受理事务**：幂等识别后检查账号可操作、无其他主动正式战、名单完整、个人冷却、全榜空闲和榜单有效性；选定对手并固定双方完整输入、榜单版本/槽位和随机初始状态，一并建立挑战、主动方角色/装备占用与全榜占用。任一校验失败不留下临时入榜、占用或新冷却。空榜入榜是独立的原子快速结果，不创建待演算操作。
3. **事务外演算**：沿用通用领取/执行代次协议，使用持久快照演算；恢复不得换对手、重抽选择或读取守方新状态。短暂忙或执行权租期结束不是释放全榜占用的理由。
4. **结算事务**：验证操作未终结、执行代次、全榜占用、原榜单版本/槽位、主动方占用/依赖及双方原内部身份仍存在、可承接既有结果；使用本场输入版本验证结果。一次提交必要入榜/换位、双方战绩、挑战者冷却、战报、操作终态、流水和占用释放。守方角色/名单的新版本不使本场失效。按[账号契约](accounts.md) Q10，停用不构成无效守方，既有竞技名单仍可被挑战，任一方在本场受理后停用也不阻止本场结算。
5. **故障取消**：按通用规则确认未成功结算且无法恢复后，原子取消并释放本场主动方和全榜占用，不换位、不入榜、不增战绩、不产生本次冷却。保留取消原因；不允许玩家看到结果后主动取消。

接受挑战期间，其他新竞技挑战直接忙碌拒绝；不得排队后悄悄用另一组排名受理。对同次请求的重试，先返回原操作状态或最终结果，而不是被它自己的全榜占用挡成一笔新失败。结算结果、战报和幂等结果一并持久化，成功丢响应只查回原结果，不重复双方战绩或刷新冷却。

正常情况下 Q2/Q6 保证原榜单在演算期不变。若恢复时仍发现槽位或榜单版本变化，应记录一致性异常并停止提交，交具名恢复或取消处理；不能覆盖新榜单、换目标重算，或仍给这场排名结果。只解除执行者租约不解除业务占用，旧执行者提交必须被执行代次及终态校验拒绝。

## 删除、异常与补位

榜内账号删除或运营移除必须与该账号的竞技名单清理、榜单补位在一个事务中完成，并遵守账号/资产未结义务保护。任何未终结竞技挑战都会使这类操作暂时拒绝，即使删除的是不参战的第三人。先检查再在另一事务删除不满足 Q6；后台、管理员也不能绕开此约束。名单变更、守方培养和公开查询不属于榜单槽位变化。

删除补位按旧版持久化后重载的有效顺序明确化：从有序槽位删除账号，保持其他账号相对顺序，再按 1/2/3/3…容量重新分档。一次事务完成并更新榜单版本，不等待下一次页面刷新。例如 A 第 1、B/C 第 2、D/E/F 第 3，移除 B 后，C/D 第 2、E/F 第 3；补位不产生战斗胜负、守冠次数或挑战冷却。

新服从空榜开始，不迁移旧排名或战绩，不需要预建排名文件。移除最后一人后必须持久保存为空榜，不能留下旧文件拒绝空写造成的“幽灵排名”；后续首人仍按空榜规则加入。不提供额外的玩家退榜/重置战绩入口。

Q7 要求完整有效的名单：不能静默跳过缺失成员后缩队，也不能将无效防守当空队判负。公共读取发现缺失账号时可显示明确异常占位并记录诊断，但不得借读取执行删除、补位或赠送排名。具名修复/移除需权限、原因及记录；修复后的挑战是新请求，不补发先前未受理挑战的胜场。异常报告不能泄露账号内部数据。

## 内容更新与展示边界

竞技名单没有永久绑定登记时内容版本。内容更新对角色统一生效，更新后新受理对局使用新定义；发布前检查所有登记名单成员及其当前状态仍合法，缺失引用或不兼容状态须先有明确迁移。不得为了发布而静默删除竞技成员、解除 48 小时限制或清空榜单。

已受理对局使用保存的旧版本执行物与输入完成，短维护发布先按内容发布契约排空；无法安全完成就阻止切换。若迁移会删除榜内账号或重排榜单，仍受 Q6 约束。合法数值更新不刷新登记时间、不重置主动冷却或战绩；维护经过的现实时间计入原冷却，不额外暂停或顺延。

公开榜单与原竞技战报查询能力按覆盖基线保留；公开字段、个人与公共战报的权限和保留期归展示专题。不因可公开排名就公开完整战术、装备内部数据或请求状态。名次、总场次、胜负平和守冠次数使用明确名称，移动端将“当前竞技名单”“可重新登记时刻”“可主动挑战时刻”分开显示，不再把挑战冷却误称体力不足。

普通团队模拟与单人模拟仍走已确认的模拟契约，不入榜、不改竞技战绩、冷却或名单；首期不凭“试阵容”新增一个可指定其他玩家为对手的竞技模拟入口。

## 后续验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 首次登记、1/5 人、0/6 人、重复/他人/失效成员、48 小时边界 | 合法名单保存；非法全部拒绝；满 48 小时可重设；重复请求不刷新登记时间 |
| 名单成员升级/转职/换装/改战术；防守方已在普通战中 | 下一次受理读取当时已提交值；本场不受受理后变化或另一场未提交成长影响 |

| 主动方受理后满 48 小时登记未来名单，再尝试删除本场已换出角色 | 新名单仅影响未来对局，本场按原快照继续；仍在本场占用的角色/装备不可冲突修改或删除 |
| 空榜首次挑战、两人同时尝试、首位再挑战 | 恰好一人无战登顶，无伪造战绩/战报/冷却；另一人按最新榜单走正式挑战；首位不能主动挑战 |
| 1/2/3/3 档容量、末档未满/已满、上一档多人 | 入榜临时位置及候选正确；等概率选上一档，不能挑战同档或指定对手 |
| 榜外胜/败/平；榜内胜/败/平 | 只有榜外胜入榜；胜仅交换具体槽位；败平不换位但双方战绩正确 |
| 首位守胜/平/负、其他档防守；反复丢冠再夺冠 | 守冠次数只在首位胜/平增加，累计值不重置；总场次 = 胜 + 负 + 平 |
| 正常胜/败/平延迟结算，结算后恰好冷却到期 | 冷却分别为结算 +60 秒/+24 小时；被动防守不改主动冷却；相等可挑战 |
| 100 行动、全灭、召唤存活、演算异常 | 按通用竞技规则裁决；无成长/掉落持久化；错误不伪装平局 |
| 多人争同一档、双方相互触发、同请求重试 | 全榜只有一场受理，其他新挑战忙时拒绝；同请求返回同一结果，无重复入榜/战绩 |
| 挑战中第三个榜内账号删号、榜外无占用账号删号 | 前者拒绝；后者不被竞技全榜占用误伤；账号其他义务仍照常校验 |
| 删除竞技成员、移除中间/首位/最后一名、公共读到失效账号 | 成员先换出；榜单按顺序原子补位；最后一人后确为空榜；读取不改排名 |
| 无效对手账号/部分缺员/全空队、异常空档 | 不受理、不自动胜/换对手/换位、不产生冷却和战绩，留下诊断 |
| 受理后崩溃、执行权接管、提交失败、成功丢响应 | 原输入恢复；主动方和全榜占用不提前释放；事务全回滚或唯一完成，旧执行者不能迟到覆盖 |
| 故障取消与旧结果同时到达、发现榜单意外变更 | 恰好一个终态；取消无新战绩/排名/冷却；异常旧结果不得覆盖榜单 |
| 守方同时购物/获得战斗收益；内容维护与迁移 | 竞技战绩增量不覆盖其他数据；发布保留已受理版本与正常冷却，不静默改名单或榜单 |

以上为实施验收要求。本次仅核对源码、文档及规则示例，没有执行竞技战斗、SQLite 并发或负载测试。
