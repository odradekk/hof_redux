## 已确认的更新策略

- Q1：当前发布的定义统一作用于已有角色和物品的派生值，不按获得时间永久分裂版本。等级、已分配属性、精炼等级及已抽取的附加效果记录不重置、不重抽；过去已经获得的成长不追溯重算。附加效果定义的规则修订参与此后的计算，已有实例仍保留自己的效果身份、来源、参数与顺序。
- Q2：使现有状态非法的变更必须提供显式迁移方案，否则阻止发布。普通下架仅关闭新的获取来源，保留已有对象的定义及使用规则；不能自动删除技能、卸装或替换物品来掩盖冲突。
- Q3：首期接受短时维护发布。暂停新的业务写操作，完成已受理战斗和进行中的短操作，检查迁移后再切换应用及内容；无法安全完成则阻止切换。为保证检查期间数据稳定，暂停范围涵盖玩家请求、后台任务及管理操作，只允许排空既有操作和发布迁移所需写入。长期拍卖、世界 Boss 及竞技防守状态的跨版本处理由对应专题明确。
- Q4：只有目标旧版本与当前存档兼容时才能直接回退；不兼容时优先前向修复，确需回退则显式迁移并验证。恢复旧数据库备份属于灾难恢复，必须说明进度损失范围，不能冒充普通发布回退。
- Q5：卵罐 1022 保留最终生效的掉落表：材料 6003 为 10%，其余 90% 不掉落。不恢复被覆盖的地图道具 8002 掉落；迁移输出唯一掉落表并保存两次定义的来源，登记为 LEG-23（保留旧行为）。

已受理操作仍使用原版本完成，不因当前版本变化取消；历史战报使用保存的事件与显示快照，不用新版数值重写旧结果。这沿用前置契约，不是新的版本兼容例外。

## 提取边界与来源覆盖

旧源码是只读证据，不作为生产加载器。输入只包含明确列出的内容定义、必要机制源码、素材及安全玩法常量；账号存档、凭据、留言、拍卖记录、运行日志等不进入提取包或发布包。静态提取不执行旧 PHP 入口，也不通过载入整个站点来取得定义。

当前[机器清单](../legacy/content-manifest.json)是调查起点，只有其中声明的引用关系已核对；它不是完整规则解析结果。正式迁移须建立逐条映射，记录旧类别/编号、文件位置及文件摘要、新 ID、处理状态、关联机制和批准差异。一个来源可拆为多个新定义，例如旧物品中的制作字段拆为配方；一个新定义也可合并重复来源，例如技能 7005。

覆盖报告必须区分：已转为可执行定义、保留但不开放、仅保留未实现内容的来源记录、经批准不迁移、仍待核对。不能用总数量相同证明语义完整，也不能让“保留但不开放”掩盖正式路径的缺失实现。生产实施验收须让全部来源条目均有去向，正式可达路径没有待核对项。

提取顺序为：固定白名单及源摘要 → 静态解析并保留重复/动态表达式诊断 → 按已核实语义规范化 → 应用逐条批准差异 → 生成编辑源及来源映射 → 结构、引用、机制与场景验证 → 构建不可变发布包。无法解释的表达式进入待核对清单，不通过执行旧代码绕过解释步骤。旧运行环境只用于前置保真契约批准的受控样例对照，不能把其数据库或整个环境打包进新游戏。

旧字段的重复赋值必须记录各次来源、顺序及最终有效值，不能仅导出最终值而丢失覆盖证据，也不能自动合并多个值。数组同键覆盖与重复 switch 分支分别解释，不使用一种“最后定义优先”策略处理所有旧重复。正式可达且未裁决的覆盖差异阻止发布；规范化规则仅作用于已核对的具体来源。

## ID 与文件组织

内容 ID 使用带类别前缀的稳定字符串，例如 `item.1000`、`skill.1000`、`map.gb0`；新内容可用固定英文短名，例如 `item.example-sword`。前缀用于引用类别校验，其余部分不用于推导职业、等级、槽位或效果。显示名称可改，ID 不随改名改变，删除后不复用为其他内容。

编辑源按类别放在 `content/`，每类使用一个或多个 JSON 文件，过大时按明确内容分组拆分；不要求每个 ID 单独建文件。转职关系、学习规则和效果池同样有独立 ID。构建时跨文件校验 ID 唯一。来源映射、未实现档案及批准差异记录放在独立的迁移资料目录，不与玩家状态或运行配置混装。发布产物可以合并文件，编辑源路径不成为游戏身份。

每个定义至少有 `id`、类型及展示信息；具体字段遵循内容模型。名称、说明和素材引用不作为规则判断输入。文件使用 UTF-8 标准 JSON；拒绝重复对象键、未知字段、错误类型和非法数值，不以静默默认值替代漏填规则。

有顺序语义的内容必须用数组：战术、效果、遭遇候选、掉落过程和附加效果来源。构建工具可以规范化无序对象键，却不能排序、去重或合并这些数组。没有值、空数组和零是不同状态，按字段契约处理。

发布包统一声明 `schemaVersion`，不允许各文件隐式选择不同格式。有限条件采用具名类型及参数，组合采用 `all`/`any`；引用字段按用途分别校验，不提供任意属性访问或字符串表达式解释器。例如 `jobId` 只能引用职业，`skillId` 只能引用技能。默认值只有在字段契约明确给出且不改变旧行为时才可省略，并在构建时展开为确定值。

## 内容类别与校验责任

| 类别 | 必须表达的规则与引用 |
| --- | --- |
| 招募模板 | 初始职业、属性、技能/装备、价格与展示；生成实例而非共享玩家状态 |
| 职业与转职 | HP/SP 系数、允许装备类型；独立转职边及有限条件，不按编号判断职业族 |
| 技能与学习规则 | 主动/被动描述、资源和时序、有序效果或具名处理器；学习职业/等级/前置技能/点数单独表达 |
| 战术条件与保护 | 有类型的参数、单位和合法区间；展示分组不是可执行条件；组合条件和保护沿用战斗契约 |
| 物品与装备 | 价格、用途、装备许可类型、占槽、效果分类、承载和基础数值；三种分类分别映射 |
| 精炼与附加效果 | 精炼次序、失败结果、效果类型与参数、适用分类；实例保存实际结果及来源，不存待抽效果 |
| 配方与效果池 | 材料/产物/费用/追加材料及随机高低阶生成；保留联合分布和随机调用次序 |
| 怪物与召唤 | 静态数值、技能/战术、保护/位置、经验/金钱/掉落；动态构建及召唤依赖显式引用 |
| 地图与遭遇 | 开放标记、进入条件、背景/素材、有序候选、权重及预览标记；零权重与不展示含义不同 |
| 城镇、商店与其他系统目录 | 正式设施、商品来源及费用等内容参数；拍卖、竞技、Boss 的状态和流程由所属模块管理，不能塞入内容文件 |
| 手册、教程与展示资料 | 按正式内容和批准差异整理文字；旧 HTML 不直接作为可信页面执行，规则引用使用内容 ID |
| 素材 | 发布内相对路径、内容摘要与旧来源；大小写精确匹配，不依赖 Windows 的大小写容错 |

静态结构校验后还须核对跨文件引用、引用类别、转职和学习条件、装备槽位/类型、效果参数、配方数量、地图候选与权重、素材及机制覆盖。概率与倍率的表示必须保留旧精度和计算顺序；不能笼统将所有小数转成整数或把全部效果当成百分比。

数量、索引、权重等整数字段须规定合法范围，并同时满足运行计算和存储范围；拒绝非有限数、负数量和溢出。可能为负的伤害/增减量按自身字段语义校验，不能一概禁止负值。具体范围应来自旧内容与机制约束，不能仅以当前最大样例值作永久上限。

## 机制登记与动态内容

普通机制通过既有类型及参数表达；特殊机制通过 `handlerId` 引用随应用发布的代码。每个处理器登记参数结构、适用阶段、允许读取的上下文、内容引用和结果类型；新增已有机制的内容只改 JSON，新增机制才改集中处理代码及相应校验。

JSON 不包含 PHP、JavaScript 或可执行表达式。不能将旧定义在某一时刻随机生成的结果固化为所有玩家共用的静态数值。怪物构建需要的时间、全服状态和随机源由调用方明确提供，并按所属玩法契约固定：普通冒险遵循冒险契约，世界 Boss 的采样时点遵循其专题；处理器不自行查询系统时间、数据库或网络。

未知处理器、参数不匹配或缺失机制都是错误，不自动退化为普通攻击。旧版未开放且未实现的内容可作为档案保留已知字段和来源，但不伪造可执行处理器；正式可达引用不能指向档案。完整但暂不开放的定义仍通过所有结构和引用校验。

正式可达性须从招募、学习、商店/制作、地图、Boss、召唤、掉落等真实入口沿引用核对；管理员测试入口和图鉴展示单独标记。缺少静态引用只能成为人工核对线索，不能直接证明废弃。完整逐技能映射和逐定义转换报告属于实施验收产物，本规划不冒充已完成全部 268 个唯一技能的转换。

开放状态附着于具体获取或使用入口，不用一个通用开关混淆“不能新获得”“已持有仍能使用”“图鉴不展示”“缺少实现”。内容下架需要检查商店、配方、掉落、招募等全部来源；只改图鉴显示不等于下架。被正式召唤或掉落路径引用的内容，也属于正式可达范围。

## 发布校验与报告

| 层次 | 阻止发布的情况 |
| --- | --- |
| 结构 | JSON 解析、重复键、未知字段、ID 冲突、类型/数值范围错误 |
| 引用 | 内容缺失、引用类别错误、正式路径引用未实现档案、未知机制或参数不匹配 |
| 语义 | 不合法槽位/条件/效果组合、无有效候选的开放地图、生成或数值不变量被破坏 |
| 素材 | 缺失或大小写不匹配；已批准的缺图只能通过显式占位映射处理 |
| 保真 | 来源无去向、正式内容仍未核对、顺序/概率/公式差异未登记批准、关键场景失败 |
| 当前状态兼容性 | 角色、物品、技能、配置及长期业务状态无法在新版本下合法解释，且无已验证迁移 |

报告同时提供可读摘要和机器结果：校验代码、严重程度、文件/内容 ID/字段位置、原因、旧来源、批准差异或例外的关联。错误使命令失败；警告必须明确处置，不能将未完成机制降为警告通过发布。无错误不等于运行验证已经通过，报告分别列出静态检查与实际执行的场景。

校验操作接收编辑源、参数结构与处理器登记、批准差异清单和素材清单，输出确定的诊断及规范化产物；有错误不产生可发布标记。兼容性检查另接收目标发布包与当前数据的一致快照，输出受影响对象/原因及所需迁移，不自行修改玩家状态。发布前在暂停写入后的实际状态上重检，不能把两次检查之间产生的角色或物品漏掉。

机器报告至少包含 `sourceFingerprint`、目标内容标识、按类别的来源覆盖计数、`diagnostics`、已执行场景及结果；每条诊断包含 `code/severity/file/definitionId/fieldPath/message/source/decisionRef`。例如新地图引用不存在怪物时，报告定位该地图候选的 `monsterId`，而不是只返回“配置错误”。玩家数据影响报告留在受控运行环境，不随公开仓库提交。

LEG-07 的缺失旧图使用显式占位素材及来源记录；占位图本身必须存在。新增缺图不自动套用这个例外。批准例外按具体条目登记，不能使用通配规则屏蔽整个类别。

## 发布包与切换

一次发布绑定应用执行物、内容快照、规则处理器、事件/随机协议版本及素材清单。内容快照是不可变的；更改一个定义也产生新的内容版本标识，定义 ID 保持不变，不能原地覆盖同名版本。人可读版本号用于发布记录，内容摘要用于验证实际字节；两者不代替来源映射。

发布清单至少包含 `releaseId`、`schemaVersion`、`contentHash`、应用/引擎/随机协议/事件格式标识、排序后的文件路径与 SHA-256、兼容的数据格式及所需迁移身份、校验报告引用。内容摘要由确定性产物清单计算，不将生成时间或摘要字段自身纳入摘要输入。相同编辑源与构建规则必须生成相同内容摘要。

发布构建在隔离目录生成完整产物，通过校验后整体交付；运行时只加载已验证快照，不逐文件读取正在编辑的 JSON。启动时核对版本配对及完整性，失败不受理业务。前端可见内容由服务端定义投影，内部掉落、隐藏规则或复现材料不因打包便利而全部公开。

维护切换使用已确认 Q3：阻止新的写操作，排空已受理战斗及短操作，在稳定状态上执行兼容性检查与明确的迁移，验证后切换。不能因为升级需要而重新抽取敌人或取消可恢复旧战斗。仍有未终结操作、未处理的旧执行者或版本依赖时，不能删除对应执行物和内容。单机停止、进程切换、备份及恢复的具体步骤归运行专题。

迁移计划至少记录目标版本、受影响对象的选择条件、计数及变化、事务/失败恢复方式、迁移身份和结果检查。测试用副本先演练；正式执行前再次检查当前状态，不以旧演练统计代替实时校验。实例身份和已保存成长不得因格式调整而丢失。

回退采用已确认 Q4：检查目标应用、内容、数据格式及当前持有/业务状态是否相容，而不是只检查文件能否替换。新版本新增内容已被玩家获得时，旧版本缺定义即阻止直接回退；数值回退也须重新检查装备、技能和角色不变量。禁止为了回退而无提示删除新物品或覆盖进度。数据库备份恢复的进度损失与旧请求隔离另按运行契约处理。

历史战报展示继续依赖保存的事件及快照；复算只使用对应旧执行物与内容，缺少时明确不可复算。历史与执行物的保存期限交给展示/运行专题，不承诺永久保存所有旧版本。

## 验收与后续专题

| 场景 | 必须成立的结果 |
| --- | --- |
| 新增使用既有机制的物品、职业、怪物 | 仅补内容与素材即可构建；新职业层级无需修改转职深度判断 |
| 新增特殊机制 | 未登记处理器时构建失败；代码、参数结构、引用声明及行为场景一起交付 |
| 引用缺失、类型混用、重复 ID/对象键、未知字段 | 报告精确位置并阻止发布，不运行时降级 |
| 同源重建、调整数组顺序 | 同源内容摘要一致；有意义的数组重排导致内容变更，并通过顺序场景发现行为差异 |
| 动态怪物、固定分母掉落和地图权重 | 保留各自分布、抽样次数和时点；未命中掉落区间仍为空 |
| 卵罐重复掉落表 | 固定 1–10000 抽样中，1–1000 为材料 6003，1001–10000 无掉落；没有地图道具 8002 的区间，两处旧来源均可追踪 |
| 未开放地图/武器、未实现技能档案 | 来源不丢失，也不会因有 JSON 或可见图鉴而自动开放 |
| 7500 缺图与新引入缺图 | 7500 使用已批准占位图；新缺图报告错误，不自动加入例外 |
| 同一剑基础攻击从 10 改 12 | 新获得与已持有均按 12 计算；精炼和效果记录不重抽，旧战报数值不改 |
| 修改占槽、删除技能或提高需求造成旧状态非法 | 无显式迁移则拒绝发布，不偷偷卸装、删技能或扣点 |
| 发布前仍有未终结战斗 | 使用原版本处理完成，否则不切换；不能发布后再丢弃其版本 |
| 发布后已有新增物品，尝试回退 | 旧版不认识当前数据则拒绝直接回退；前向修复或明确迁移，不恢复旧备份冒充无损回退 |
