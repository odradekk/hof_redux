# 首期公开运营采用 SQLite

首期选择 SQLite WAL，部署于单台服务器的本机持久磁盘，以约 100 人在线作为负载测试场景。相较于起初提出的 PostgreSQL，当前优先降低部署和维护成本；战斗主要在内存中演算，通过短事务提交结果，实际承载能力仍须结合共享 Boss、拍卖和奖励结算进行验证。

SQLite 同时只有一个写入者，WAL 不消除写入竞争。资产变更必须有事务、状态校验和重复请求处理，数据库备份须保持一致性。未来若需要多机共享写入，或实测持续写入等待成为瓶颈，再评估数据库迁移；本次不承诺无成本迁移或预先实现双数据库支持。

依据：已批准的架构讨论，以及 SQLite 官方的 [适用场景](https://www.sqlite.org/whentouse.html) 与 [WAL 限制](https://www.sqlite.org/wal.html)。具体驱动、运行时、事务策略、备份与恢复指标留待 Wayfinder 详细规划。
