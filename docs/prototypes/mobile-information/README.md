# 手机信息结构原型 · 待用户试用

用于[手机端编队、战术、装备与战报的信息结构](https://github.com/odradekk/hof_redux/issues/14)。用户已在 Q2 选择第二轮方向：A 的独立页面与主导航＋B 的角色切换，C 只保留准备状态摘要。D 是据此制作的待试用组合版；这项选择不是完整页面契约确认，也不表示真实手机验收通过。

## 打开

直接双击 `index.html`，无需安装依赖。也可以在仓库根运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory docs/prototypes/mobile-information
```

打开 `http://127.0.0.1:8765/?variant=D`，无参数也默认进入 D。旧 A/B/C 保留用于比较；第一轮完整快照为提交 `87bd94b`。底部原型箭头可循环切换四个方案；非表单控件聚焦时也可使用键盘左右键。参数保留在 URL，刷新后方案保持、模拟数据重置。

顶部可预览 320 / 390 / 430 px 或桌面布局。它只是容器宽度预览，不能代替真实手机浏览器、软键盘和触控验收。服务仅绑定本机，手机不能直接访问电脑的 `127.0.0.1`。本轮不启用外网托管或修改防火墙。

## 比较什么

| 方案 | 信息结构 | 需要验证的取舍 |
| --- | --- | --- |
| A 冒险优先 | 出战准备为主页，成员、培养、出发分步访问 | 主线是否清楚；培养是否跳转太多 |
| B 角色工作台 | 手机顶部选人，桌面固定左列；右侧角色培养和出战页面 | 连续配置多个角色是否方便；出发入口是否易找 |
| C 紧凑总览 | 单页分区展开；桌面分两列 | 信息是否过密；长战报是否影响返回其他操作 |
| D A＋B 组合 | 单一底部主导航、角色页内部切换、全局处理提示、战报状态就地展开 | 编辑与出战是否清楚；切换是否连续；长战报是否能保持阅读位置 |

第二轮重点试用：

1. 进入“角色”，切换到第六至第八名角色；离开到城镇，再回到角色页，核对编辑对象仍是刚才那名。样例共八名角色，并非新的持有数量上限。
2. 通过“调整出战成员与阵位”查看全体角色；已选五人时再选一人应拒绝，先换下一人后可加入。选择培养对象不会改变出战成员。
3. 受理一场正式战或模拟战后进入其他页面，顶部仍显示各自处理状态；点击提示返回状态卡，正式与模拟分别查询。底部主导航持续可用。
4. 在战报后半段展开一个步骤，再展开/收起其双方状态；按钮只更新局部内容，不重建整页、不跳回顶部。每一步的展开状态独立保留，离开战报或切换报告示例后重置。

组合版没有常驻步骤条，角色页不把培养当作每次出战的必经步骤。手机角色列表可横向滑动，也可用“定位角色”选择；桌面显示左侧列表。导航和原型切换器分开，只有原型切换器属于试验工具。

每种方案至少试：选择成员和阵位；为阿岚比较并替换两把短剑；移动完整 AND 战术组、编辑阈值、保存并测试；学习技能；查看 24 步战报中的指定步骤及 7 名敌人。可以混合选择各方案的部分设计。

顶部“试用任务与异常场景”可以切换下次提交：正常、容量满、版本冲突、响应丢失、待人工、故障取消、暂停。已受理状态通过“刷新处理状态”推进，未知状态先查询原操作；没有真实请求、计时器、战斗演算或资产持久化。正式战与模拟战分别处理，角色占用按正式出战成员确定。

## 范围与限制

- 全部队名、人名、数值、条件、学习样例、结果与流程状态都是模拟。真实名称及素材不表示复刻了对应完整玩法。前端最终使用 Vue，本原型为无依赖 HTML/CSS/JS，不直接升格为生产代码。
- 可编辑养成角色仅阿岚。其他角色可选入队、改前后排和切换查看；交易、Boss、竞技、资料、社区、账号只验证导航和摘要，不实现业务。
- 战报是独立预置的静态展示样例，不是模拟提交按钮计算的结果，也没有实现事件引擎。阵位、数值和事件用于检查长内容阅读，不是可复现战斗证据。
- 当前/备用战术及容量变化为模拟；容量数字不是旧公式实现。超限完整组隐藏，不显示灰行。没有加入成员拖拽排序、额外战术方案或游戏新系统。
- 刷新清空本地模拟状态；切换方案保留模拟状态。所有“保存”“学习”“更换”仅作用于当前页面内存。
- 原型分支 `prototype/mobile-information` 与主分支隔离。用户反馈后再形成正式页面与操作契约；本议题尚未完成。

## 本轮核验

已检查 JavaScript 语法、UTF-8、静态资源存在性及 10 个素材与旧文件的字节一致性；本机服务返回 HTTP 200。脚本执行检查确认三种布局均能生成、正式战与团队模拟可并行、未出战角色可编辑，以及故障取消后体力未扣、预留释放、记忆保留。独立检查已纠正正式/模拟状态混用与全账号占用。

第二轮另检查 D 渲染、八名角色与五人出战限制、记住编辑角色、正式/模拟全局状态、战报局部展开不重绘或滚动，以及历史阵容不随当前角色阵位改变。第一轮评审 agent 的结论属于代码结构意见，已作为组合方向的参考，不算用户触控反馈。

当前会话没有可用的浏览器控制连接，未完成浏览器可视化检查；真实手机触控、软键盘、窄屏换行及组合版实际试用反馈仍待验收。不要把容器宽度选项或脚本检查视为手机验收通过。
