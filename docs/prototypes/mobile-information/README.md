# 手机信息结构原型 · 待用户试用

用于[手机端编队、战术、装备与战报的信息结构](https://github.com/odradekk/hof_redux/issues/14)。用户已在 Q2 选择第二轮方向：A 的独立页面与主导航＋B 的角色切换，C 只保留准备状态摘要。D 是据此制作的待试用组合版；这项选择不是完整页面契约确认，也不表示真实手机验收通过。

收敛轮：用户确认将编队入口上提、清理空状态条、增加槽位筛选，并在 Q4 确认每角色战术草稿在当前页面会话内保留。正式与团队模拟只使用已保存配置；“保存并单人测试”先保存再固定本次测试输入。页面契约草案另位于主工作区 `docs/design/mobile-interaction.md`，尚未定稿，不将本分支原型当作领域规则来源。

## 打开

直接双击 `index.html`，无需安装依赖。也可以在仓库根运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory docs/prototypes/mobile-information
```

打开 `http://127.0.0.1:8765/?variant=D`，无参数也默认进入 D。旧 A/B/C 保留用于比较；第一轮完整快照为提交 `87bd94b`。底部原型箭头可循环切换四个方案；非表单控件聚焦时也可使用键盘左右键。D 的单步战报页内，左右键用于前后翻页，不切换方案。参数保留在 URL，刷新后方案保持、模拟数据重置。

直接试用分页战报：`http://127.0.0.1:8765/?variant=D&view=report`。该链接进入摘要目录，不保存正在阅读的步骤号。

顶部可预览 320 / 390 / 430 px 或桌面布局。它只是容器宽度预览，不能代替真实手机浏览器、软键盘和触控验收。服务仅绑定本机，手机不能直接访问电脑的 `127.0.0.1`。本轮不启用外网托管或修改防火墙。

## 本轮：战场版与明细版

要回答的问题：保留同一套分页操作后，把行动者、目标和战场放在主要位置，是否比逐节列出明细更像在复盘一场战斗？用户经对比评审已同意以战场版为主要呈现，保留可展开的完整记录；明细版继续留在原型中供核对。具体视觉效果与手机操作尚待实际验收。

- 战场版（默认）：`http://127.0.0.1:8765/?variant=D&view=report&presentation=battle`
- 明细版：`http://127.0.0.1:8765/?variant=D&view=report&presentation=detail`

战场版铺满战报内容区，减少窄屏上的嵌套边框与留白，应用页头及主导航沿用其他页面。战报上方可以切换表现，保留当前步骤，URL 保存表现选择；刷新仍回目录。战场版先显示行动者、目标和关键事件，敌我上下对峙，前排靠近交战前线、后排位于外侧；人数较多时自动换行，不裁剪单位。320px 预览阵型每行两名，更宽手机每行三名。桌面沿用上下阵型并增加每行容量。

伤害与治疗数值来自逐条结构化样例事件，单位旁的“HP 净变”才是本步前后差值，两者不混用。完整事件与前后数值放在可展开详情中，行动计数、事件编号与保留期限移入次要说明。死亡、召唤、蓄力等同时使用文字与颜色；不增加动画或新素材。

本轮收敛补充：第 6 步直接展示“本步计算收益：金钱 +120”，与目录中的整场已结算收益区分；模拟战明确标注不产生正式收益。第 17、24 步显示待机/防御及 HP/SP 未变化。第 23 步的死亡目标标明“本步阵亡”，常规阵型继续展示步骤结束状态；死亡召唤物移除，死亡头像、事件和前后数值仍可核对。

建议比较第 6 步击杀、第 10 步召唤、第 12 步双目标攻击、第 13 步攻击后毒发、第 18 步咏唱、第 23 步召唤物死亡；先看是否能迅速分清行动者与目标，再展开明细核对。两种表现可以在同一步切换，返回目录仍定位进入细读前的条目。

`report-action-fixtures.js` 为每步明确提供行动者、主动目标、动作类型及逐条事件属性，与 `report-prototype.js` 的固定状态配对；`report-battle-view.js/.css` 只负责表现对比。这是一次性展示样例，不是已定稿的生产事件协议。

## 比较什么

| 方案 | 信息结构 | 需要验证的取舍 |
| --- | --- | --- |
| A 冒险优先 | 出战准备为主页，成员、培养、出发分步访问 | 主线是否清楚；培养是否跳转太多 |
| B 角色工作台 | 手机顶部选人，桌面固定左列；右侧角色培养和出战页面 | 连续配置多个角色是否方便；出发入口是否易找 |
| C 紧凑总览 | 单页分区展开；桌面分两列 | 信息是否过密；长战报是否影响返回其他操作 |
| D A＋B 组合 | 单一底部主导航、角色页内部切换、全局处理提示、战报摘要目录与单步阅读 | 编辑与出战是否清楚；相邻步骤是否易读；返回目录是否能保持来源位置 |

当前重点试用：

1. 进入“角色”，切换到第六至第八名角色；离开到城镇，再回到角色页，核对编辑对象仍是刚才那名。样例共八名角色，并非新的持有数量上限。
2. 通过角色切换区顶部的“出战 5/5”查看全体角色；已选五人时再选一人应拒绝，先换下一人后可加入。选择培养对象不会改变出战成员。
3. 受理一场正式战或模拟战后进入其他页面，顶部仍显示各自处理状态；点击提示返回状态卡，正式与模拟分别查询。底部主导航持续可用。
4. 在战报目录后半段进入第 18 步，查看咏唱开始；前后翻页并输入 20 跳到释放治疗，返回目录应回到第 18 步的来源位置。第 6 步把伤害、死亡和收益记录放在同页；第 10 步显示召唤后的 7 名敌人，第 23 步保留召唤物死亡事件并将其移出后续阵型。首尾不循环，非法或越界步骤不能跳转；长页可纵向滚动。
5. 分别修改两名角色的战术，再切换回来核对草稿。准备页显示有未保存战术，但出战不会自动保存；在受理状态中展开“本次固定的已保存战术”，核对实际固定的有效规则。修改冲突或容量满也保留草稿。刷新或关闭可能丢失，浏览器允许时触发未保存提示；不保证所有关闭方式均会弹窗。
6. 阿岚装备页有 13 件独立样例，其中当前穿戴 1 件；可按槽位和名称/样品编号筛选，按回车或“筛选”应用。战戟仍可查看并说明职业/承载不符，其他槽位目前展示无样例的空结果；没有新增真实游戏装备。

组合版没有常驻步骤条，角色页不把培养当作每次出战的必经步骤。手机角色列表可横向滑动，也可用“定位角色”选择；桌面显示左侧列表。导航和原型切换器分开，只有原型切换器属于试验工具。

每种方案至少试：选择成员和阵位；为阿岚比较并替换两把短剑；移动完整 AND 战术组、编辑阈值、保存并测试；学习技能；查看 24 步战报中的指定步骤及 7 名敌人。可以混合选择各方案的部分设计。

顶部“试用任务与异常场景”可以切换下次提交：正常、容量满、版本冲突、响应丢失、待人工、故障取消、暂停。已受理状态通过“刷新处理状态”推进，未知状态先查询原操作；没有真实请求、计时器、战斗演算或资产持久化。正式战与模拟战分别处理，角色占用按正式出战成员确定。

## 范围与限制

- 全部队名、人名、数值、条件、学习样例、结果与流程状态都是模拟。真实名称及素材不表示复刻了对应完整玩法。前端最终使用 Vue，本原型为无依赖 HTML/CSS/JS，不直接升格为生产代码。
- 全部八名角色可编辑各自战术；装备和技能学习仍仅阿岚可编辑，其他角色可选入队、改前后排和切换查看。交易、Boss、竞技、资料、社区、账号只验证导航和摘要，不实现业务。
- 战报是独立预置的静态展示样例，不是模拟提交按钮计算的结果，也没有实现事件引擎。`report-prototype.js` 为 D 提供 24 个分组步骤及前后状态：一次行动和其关联事件同页，蓄力/咏唱开始与释放分开。翻页只读取这些状态，不重新演算。24 步不是正式行动上限，步骤号也不是回合数。阵位、数值和事件用于检查长内容阅读，不是可复现战斗证据。
- 当前/备用战术及容量变化为模拟；容量数字不是旧公式实现。超限完整组隐藏，不显示灰行。没有加入成员拖拽排序、额外战术方案或游戏新系统。
- 刷新清空本地模拟状态；切换方案保留模拟状态。所有“保存”“学习”“更换”仅作用于当前页面内存。
- 原型分支 `prototype/mobile-information` 与主分支隔离。用户反馈后再形成正式页面与操作契约；本议题尚未完成。

## 本轮核验

已检查 JavaScript 语法、UTF-8、静态资源存在性及 10 个素材与旧文件的字节一致性；本机服务返回 HTTP 200。脚本执行检查确认三种布局均能生成、正式战与团队模拟可并行、未出战角色可编辑，以及故障取消后体力未扣、预留释放、记忆保留。独立检查已纠正正式/模拟状态混用与全账号占用。

第二轮（历史提交 `a2e618d`）另检查 D 渲染、八名角色与五人出战限制、记住编辑角色、正式/模拟全局状态、战报局部展开不重绘或滚动，以及历史阵容不随当前角色阵位改变。第一轮评审 agent 的结论属于代码结构意见，已作为组合方向的参考，不算用户触控反馈。

收敛轮检查各角色草稿独立、出战输入使用已保存副本且可在状态卡核对、保存及测试受理失败保留草稿、保存并测试固定当前角色、关闭提示、装备筛选的两种空结果及不可装备/占用原因、搜索文本转义、四方案仍可生成。容量下降只影响下一次有效输入，隐藏组底层保留，不改已受理快照。无业务状态时 D 不渲染空提示条。底栏 `84px` 偏移仍仅为原型切换器留位，正式界面不能继承；安全区域留白独立处理。

分页轮按用户确认的新方向替换 D 的就地展开；此前版本仍可在 `8e6f8c8` 查看。脚本执行检查覆盖 24 步前后状态连续、事件顺序、蓄力/咏唱与行动计数区分、伤害/死亡/收益分组、召唤生命周期、首尾边界、合法及非法跳转、返回目录的滚动与焦点恢复、历史数据独立及四种布局生成。独立代码评审未发现分页实现的阻塞项；本轮仍只完成代码与模拟 DOM 检查。

战场轮脚本检查覆盖 24 步结构化事件与 HP/SP 前后数值核对、两种表现全部步骤生成、无缺失明细或无效值、伤害/治疗与净变化区分、召唤生命周期、切换表现后的步骤及目录位置/焦点保持。独立评审指出的行动/结果混用、第 23 步事件语义错位、目录切换定位和模拟战权限文案已修正；针对修改重新核对通过。

表现收敛轮核对正式/模拟的计算收益提示、待机与防御、死亡当步标记和下一步消失、战场/明细背景切换及离开战报后的页面样式隔离；分页、完整事件及四方案生成继续通过脚本检查。

当前会话没有可用的浏览器控制连接，未完成浏览器可视化检查；真实手机触控、软键盘、窄屏换行及组合版实际试用反馈仍待验收。不要把容器宽度选项或脚本检查视为手机验收通过。
